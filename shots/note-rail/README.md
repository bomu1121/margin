# 笔记右栏重构：事实 / 标注 / 关联 / 信息

[事实](01-facts.png) · [标注](02-annotations.png) · [关联](03-links.png) · [信息](04-info.png) · [从事实详情返回](05-return-highlight.png)

## 为什么改成标签页

原来的右栏把「来源与制作 / 事实 10 张卡 / 关系图 / 标注 / 文件」纵向堆在一起。事实卡片一多，标注、关系图和文件全部被推到下面；而事实卡片又把引用笔记、来源、ID、两种操作都塞进卡片，列表实际承担了详情页。

现在的右栏是一个固定头部 + 四个标签页：

- **事实**：只做索引。每行 = 状态 + 事实全文（最多 3 行）+ 来源数 + 关联数；整行点进事实详情，右侧只剩「定位」小图标和进入箭头。
- **标注**：按正文顺序，保留 composer、标注正文、定位/删除、锚点失效。正文点「+」会自动切到这个 tab 并把焦点放进输入框。
- **关联**：只放局部关系图，不再和事实列表抢纵向空间。
- **信息**：把原来的「来源与制作」和「文件」合并；只保留来源标题/UP、运行、生成时间、制作台入口、文件路径、复制路径和标签台。项目名、标注数等重复信息删掉。

## 设计取舍

- **事实卡不再展示来源域名、证据引文、ID、详情/定位两个文字按钮**。这些属于事实详情页；右栏只需要回答「本页有哪些事实、哪些需要关注」。
- **事实按需要关注排序**：disputed → unsupported → candidate → verified；「只看需关注」一键过滤。
- **标注优先于元数据**：标注是用户自己写的内容，来源/文件是元数据；后者收进「信息」tab。
- **关系图保留但不再常驻**：它是辅助视图，不应该把事实列表和标注一起挤下去。
- **标签页会隐藏同时查看**：这是取舍；换来的是每个模块都有完整高度，不用在 380px 宽的栏里滚过 10 张事实卡才能看到标注。

## 诚实边界

- 标签页切换没有做左右方向键导航，只做了点击；ARIA 只到 `role=tab` / `aria-selected`。
- 事实列表默认 10 条全部渲染（当前数据量），没有虚拟滚动；事实很多时需要再加「只显示前 N 条 / 展开」。
- 关联 tab 的图仍是原来的深色卡片，和浅色 rail 是对比色，不是完全同色系。
- 截图 02/03/04 是最终包实测；01 也是最终包。

## 返回上下文

从笔记右栏点事实进入详情后，返回按钮是「返回笔记」；返回后会自动切回事实 tab、滚到原事实并短暂高亮（见 05-return-highlight.png）。从事实库进入则显示「返回事实库」。
