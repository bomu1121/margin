# 事实库与笔记关联：落地设计

> 状态：**Phase 1/2/3/4/5 已落地**（2026-11-08）：事实库、单条重新核验、关系分类、人工合并与撤销、图谱笔记—事实—来源；事实详情页与抽取时语义归并已接。整库历史事实的自动重组仍未做。
> 目标：把溯源从“每篇笔记末尾的一份报告”改成“事实是独立实体，笔记提及事实，事实关联来源与证据”。
> 本文记录当前已实现的部分、数据契约、迁移方式和仍未做的部分。

## 1. 核心结论

1. **事实是一等实体**，不是笔记的附件，也不是报告里的一个段落。
2. 笔记只保存“提及关系”：哪篇笔记、哪句原文、哪次运行（`run_id`）。
3. 事实保存规范文本、状态、来源、引文和核验历史；同一事实可以被多篇笔记复用。
4. 笔记页的 Markdown 只负责可读性；事实侧栏和事实库从 SQLite 读取。
5. **事实库列表只做索引**；一条事实是像笔记一样的一页文档，引用笔记、证据、关系、核验历史都放在详情页。
6. 溯源抽取后先做一次“同一事实”语义归并；能归入已有事实就只加 mention，不再新建一条。
7. 新生成的笔记不再把整份 `## 溯源` 报告追加到 Markdown 末尾；旧笔记里已有的文本保留，不重写用户文件。事实侧栏和事实库是新的读取入口。

## 2. 关系图

```text
Note 1 ──< note_fact_mentions >── 1 Fact 1 ──< fact_evidence >── 1 Source
                                  │
                                  ├──< fact_checks >── 核验历史
                                  └──< fact_relations >── 相关/冲突/相同事实
```

- `note_fact_mentions` 是笔记和事实的多对多桥；带 `run_id`，避免历史运行把旧事实堆到当前笔记。
- `fact_evidence` 是事实和来源之间的证据关系，带 `relation`（supports/contradicts/mention）和 `quote`。
- `fact_checks` 记录每次核验的 verdict、检索词、模型和证据快照。
- `fact_relations` 保存**候选关系**：规范化文本的 CJK bigram Dice ≥ 0.34 才建边；≥ 0.62 且数字集合一致记 `same_as`，≥ 0.55 且两边都有数字但集合不同记 `contradicts`，其余记 `related`。三者都是候选，不是语义终审，也不会自动改事实状态。

## 3. 数据表

### 3.1 facts

| 字段 | 说明 |
| --- | --- |
| `id` | `fact_<sha256(normalized)[..12]>`，同一规范化文本稳定复用 |
| `text` | 事实主张原文 |
| `normalized` | 去空白/标点后的精确去重键 |
| `status` | `candidate` / `verified` / `disputed` / `unsupported` |
| `created_at` / `updated_at` / `last_checked_at` | 生命周期 |

### 3.2 note_fact_mentions

| 字段 | 说明 |
| --- | --- |
| `fact_id` / `note_id` | 多对多关系 |
| `run_id` | 产生这条提及的 `production_jobs.id` |
| `quote` | 笔记正文里的支撑句（优先 source_quote） |
| `section` / `block_id` | 预留锚点；当前 block_id 由前端运行时解析 |
| `stance` | 当前固定 asserts |

同一 `(fact_id, note_id, quote)` 不重复插入。

### 3.3 fact_sources / fact_evidence

- Source 按 URL 唯一；保存标题、域名。
- Evidence 按 `(fact_id, source_id, quote)` 唯一；关系由 verdict 映射：
  - 外部可印证 → `supports`
  - 存在争议 → `contradicts`
  - 其他 → `mention`
- 来源正文本身没有长期保存；当前保留的是引文和 URL。网页全文在核验 checkpoint 成功后会被清理。

### 3.4 fact_relations

| 字段 | 说明 |
| --- | --- |
| `fact_id` / `other_fact_id` | 两个事实；每个方向各存一条，读取时双向遍历 |
| `relation` | `same_as`（人工合并候选）/ `contradicts`（数值不一致候选）/ `related`（一般相关） |
| `confidence` | 当前是规范化文本的 Dice bigram 相似度（0–1），不是语义置信度 |
| `created_at` | 生成时间 |

生成规则：
- 对事实 A 和库内其他事实 B 计算 normalized 文本的 bigram Dice；
- `similarity >= 0.34` 才写入；`same_as` 阈值 0.62，`contradicts` 阈值 0.55；
- `contradicts` 要求两边都能抽出数字，且数字集合不完全相同；只有一边有数字时不会判冲突；
- 每次插入最多取最相似 3 条；
- 每条事实只对自己的候选写一条有向关系；`related_for` 同时查正向和反向，所以双方都能看到。这样新事实无论 ID 大小都能连到已有事实（之前只允许 `fact_id < other_fact_id`，会漏掉后创建但 ID 更大的事实）；
- `relation_version = 3` 的迁移会在启动时重建已有事实的关系。初始真实库 10 条事实只产生 1 对相关（小布什两场战争，0.377），第二高的“中期选举 120 亿美元 vs 托育补贴 120 亿美元”只有 0.273，未误连；修正方向后重建为 22 行双向关系（11 对）。

### 3.5 fact_checks

每次 `record_verification` 写一条：
- `verdict`
- `provider` / `model`
- `queries_json`
- `evidence_json`
- `checked_at`

为后续“重新核验/审计”保留历史。

### 3.6 fact_merges

人工确认合并时写审计记录：

| 字段 | 说明 |
| --- | --- |
| `target_fact_id` | 保留的事实 |
| `source_fact_id` | 被合并并删除的事实 |
| `target_text` / `source_text` | 合并当时的文本快照 |
| `source_status` | 被合并事实的状态 |
| `snapshot_json` | 合并前双方状态 + 被合并事实的 mention / evidence / check 快照 + moved id |
| `merged_at` / `undone_at` | 合并时间 / 撤销时间（0 表示未撤销） |

合并规则：
- 只允许被判定为 `same_as` 的两条事实，后端会重新计算；`contradicts` 或相似度不足直接拒绝；
- 必须由用户在事实库弹窗里确认，没有自动合并；
- 提及、来源证据、核验历史转移到保留事实；重复的 `(fact, note, quote)` 和 `(fact, source, quote)` 自动去重；
- 被合并事实删除；关系重新按保留事实计算；
- 快照含 `version=2`、合并前双方完整状态、被移动的 mention/evidence/check id；新版记录可以撤销，旧版快照只能查看；
- 撤销时删除已移动记录、恢复源事实及其提及/证据/核验历史、恢复保留事实合并前状态，并写 `undone_at`；
- 状态合并保守：两边相同则保持；一方 candidate 则取另一方；两边都是 verified 才保持 verified；其余非 candidate 冲突记为 disputed。

## 4. 溯源时的语义归并

```text
抽取 claims
  → 对每条 claim 找 top 5 现有事实候选（词面/normalized）
  → 一次模型调用：判断是否同一主体+同一指标+同一时间+同一数值口径
  → 命中：只给现有事实加 mention，不新建事实，也不重复检索
  → 未命中：新建事实候选，继续检索/核验
  → 兜底：词面 same_as 直接复用；模型失败则全部作为新事实
```

- 归并判断用 `trace_match_system`；输入带候选事实 id/text/status，输出 `{index, factId|null, reason}`。
- 结果是 checkpoint `trace:match:<payload hash>`，续跑不重复调用模型。
- 归并命中不会改已有事实的状态/证据，只增加引用；新笔记的 claim 作为 mention 的 quote 保留。
- 归并模型失败或返回候选外 id 时降级为词面 `same_as`，再降级为新事实；不会因为归并失败阻塞整条溯源。
- 抽取 prompt 同时要求“同一句/同一段里围绕同一人物、机构、指标、时间范围的并列子断言合并成一条”，从源头减少碎片。

## 5. 生命周期

```text
抽取 claims
  → facts(status=candidate) + note_fact_mentions(run_id)
  → 检索 / Fetch
  → 逐条核查
  → facts(status=verified/disputed/unsupported)
  → fact_evidence + fact_checks
```

这解决了旧实现的两个问题：

1. 事实在核验之前就存在，核验失败不会让它消失；
2. 事实状态和证据是数据库记录，不再只存在于笔记末尾的文本里。

## 6. 笔记锚点

- 主张抽取 Prompt 要求 `source_quote`：从正文原样复制的支撑句。
- Rust 端校验 `source_quote` 是否在正文中；不在则回退到 claim，避免存一条不存在的锚点。
- 当前不把 block_id 写进 Markdown：Markdown 解析器在前端生成 FNV block ID，后端无法可靠复用。
- 笔记页用 `quote`/claim 在 `parsed.allBlocks` 中做文本匹配，找到块后滚动并短暂高亮。
- 旧 trace 迁移没有 source_quote，因此定位可能失败；UI 会明确显示“没有在正文里定位到原句”。

## 7. 旧 trace 迁移

`FactStore::open` 执行一次性迁移：

- 读取每篇笔记**最新一次** `production_jobs.result_json.trace[]`；
- 将 claim 写入 facts、mention、source、evidence；
- 用 `fact_meta.seed_version = 2` 防止重复；这个检查只能比较 `"2"`，不能跟着关系版本一起改（开发中曾误改成 `"3"`，导致启动时重新 seed 并清空旧事实，已修复并加回归测试）；
- 迁移时的真实笔记回填结果：10 条事实、10 条提及、4 条 `verified`、6 条 `disputed`。

不再把同一笔记所有历史运行的 trace 全部堆进事实侧栏。旧笔记的 `## 溯源` 文本保留，不重写用户文件。

## 8. UI

### 8.1 笔记页右栏

右栏不再纵向堆叠五个模块，而是一个固定头部 + 四个标签页：

- **事实**：只做索引。每行 = 状态 + 事实全文（最多 3 行）+ 来源数 + 关联数；整行进事实详情；右侧只有定位图标和进入箭头。按 disputed → unsupported → candidate → verified 排序，支持「只看需关注」。
- **标注**：按正文顺序；composer、标注正文、定位/删除、锚点失效都在这里。正文点「+」会自动切到标注 tab 并把焦点放进输入框。
- **关联**：局部关系图；不再与事实列表争纵向空间。
- **信息**：合并原「来源与制作」和「文件」；只保留来源标题/UP、运行、生成时间、制作台入口、文件路径、复制路径和标签台。

状态色：
- `verified`：绿色，有证据支持
- `disputed`：金色，存在争议
- `unsupported`：灰色，未找到证据
- `candidate`：蓝色，未核验

事实行不显示来源域名、证据引文、ID、详情/定位文字按钮；这些都在事实详情页。右侧栏只回答「本页有哪些事实、哪些需要关注」。

### 8.2 事实库列表

- 路由 `#/facts`；列表只做索引，不展示引用笔记/证据/操作；
- 每行只有状态、事实全文、`N 篇笔记引用 · M 条证据 · K 个关联`；
- 点整行进入事实详情页；不再有「打开笔记」主按钮；
- 状态筛选、文本搜索、只看冲突、合并记录保留在列表层；
- 搜索仍匹配事实全文；同一笔记多次运行只算一篇笔记。

### 8.3 事实详情页

路由 `#/facts/:id`，布局像笔记：

- 头部：事实全文、状态、引用笔记数、证据数、相关事实数、最近核验；
- 「引用这篇事实的笔记」：按笔记聚合，列出标题、UP/日期、每个 run 的原文 quote、打开笔记；
- 「证据」：来源域名、支持/冲突、逐字引文、打开来源；
- 「相关与冲突」：`same_as` / `contradicts` / `related` 候选，点击进入另一条事实；
- 「核验历史」：每次 verdict、provider/model、检索词、证据数、时间；
- 右栏：状态、引用/证据/关联计数、创建/最近核验、检索词、重新核验、合并重复；
- 「打开笔记」只在引用关系里出现，不再出现在列表主位置；
- **返回上下文**：从笔记右栏进入时，返回按钮是「返回笔记」；返回后自动切事实 tab、滚到原事实并短暂高亮。从事实库进入时是「返回事实库」。

### 8.4 图谱

- 默认「笔记 + 事实」层；来源层默认隐藏，打开后来源是灰点，避免长 URL 和标签互相遮挡；
- 事实节点按状态着色，点击显示全文、状态、提及笔记、来源和「在事实库打开」；
- 来源节点点击显示 URL、关联事实和「打开来源」；
- 证据引文会去掉 `<sup>` 等 HTML 标记，避免把脚注数字当成正文。

### 8.5 任务详情的溯源 tab

任务详情「溯源」不再读任务创建时的旧快照，而是按 `noteId + runId` 读事实库当前状态；合并、重新核验后的状态会直接反映在这里。

## 10. 诚实边界

- **关系判定是词面 + 数字规则，不是语义模型**：`same_as` / `contradicts` 都只是候选。溯源时的语义归并会额外调用一次模型，但它只处理“新 claim 对已有事实”的同一性，不是整库聚类。
- **历史 16 条事实没有自动重组**：抽取 prompt 和语义归并只影响新运行；库里已有的复合/原子碎片仍然存在，需要人工合并或后续“整理事实”动作。
- **人工合并是破坏性操作**：被合并事实会删除；新版记录可通过「合并记录」撤销，旧版快照只能查看。合并后的状态是保守规则，不是新的核验。
- **拆分不迁移证据**：M2 把 evidence/citation 留在父事实，子事实默认无来源；这不是“拆完就有证据”，需要逐条核验。撤销只删本次新建且仍干净的子事实；已有原子事实保留。
- **语义归并只加 mention，不重新核验已有事实**：新笔记引用一条已有事实时，复用它的当前状态和证据；如果这条事实本身没有被核验过，新笔记也不会自动补核验。
- **图谱只画笔记—事实—来源**：事实之间没有单独的 same_as/contradicts 边；来源层是灰点，不显示 URL 标签；布局在 13 篇笔记/16 条事实下验收，规模更大时可能拥挤。
- **冲突样本不足**：当前 16 条事实没有真实数值冲突，`contradicts` 只有单元测试；阈值 0.55 没有标注集。
- 相关关系只是词面重合，不是语义判断；`confidence` 不能当“事实相关概率”展示，UI 只写“词面重合 38%”。
- **笔记锚点是文本匹配**：不是持久 block ID；改写/重复段落可能定位失败。
- **历史 trace 迁移不重写 Markdown**：旧笔记仍然同时有 `## 溯源` 文本和事实侧栏，二者短期会重复。
- **来源正文未长期保存**：只保存 URL、标题、引文；无法在 UI 里回看抓取全文。
- **相关关系会漏也会误**：0.34 的阈值是在当前 10 条事实/45 对上定的；同主题但用词不同的主张会漏，模板化长句可能误连。没有大规模标注集，不能声称精度。
- **合并阈值同样没有标注集**：0.62 只用于拦截明显不同的文本；当前真实合并的 5 对都是 0.65–0.94，且经过人工确认。它不能替代语义判断。
- **事实状态不是事实真值**：`verified` 只表示当前证据支持，不表示绝对正确；来源本身可能错误。
- **`domain` 是模型分类，不是硬事实**：主张抽取模型判断 history/general，可能把时政评论里的历史引用标成 history，也可能漏标历史主张；当前没有手动纠正 UI。它只决定显示「史料」还是「网络证据」，不改变事实内容。
- **旧合并记录不可撤销**：旧版 `snapshot_json` 没有 target 状态和 moved id；UI 会显示“旧版记录，无完整快照”。当前库的记录都是新版，可撤销。
