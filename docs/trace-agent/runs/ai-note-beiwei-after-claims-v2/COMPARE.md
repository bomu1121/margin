# 同一篇北魏长稿：改前 vs 改后

素材与任务相同：`beiwei-material.md`（旧北魏笔记正文）+ `beiwei-task.md`。
两次 AI 成稿的正文不是逐字相同（模型有随机性）；真正受控的差异是 **claims 协议** 和 **cite_agent 读取方式**。

## 1. 结构

| 指标 | 改前（P169） | 改后（P170） |
| --- | --- | --- |
| 标题 | 十五万兵去受降… | 十五万人去受降… |
| 正文 | 2,810 CJK | 3,088 CJK |
| H2 | 9 | 12 |
| 视觉块 | 4 | 2 |
| 字节 | 17,046 | 14,287 |
| claims 块 | 无 | 8 条，全部 `待查` |
| AI 成稿耗时 / 成本 | 84.7s / ¥0.0905 | 84s / ¥0.0574 |

> 成本差主要来自缓存，不是同一口径；不能拿这两个数直接比较模型价格。

## 2. 结构差异

改前 8 节 + 一句话收束：

```text
一、时间线
二、决策链
三、两个战场，只讲了一个
四、彭城战术复盘
五、数字盘点与口径问题
六、引语核查
七、三种解释摆在一起
八、待查清单
一句话收束
```

改后 12 节：

```text
一、开局：长江以南已定，长江以北未定
二、466年11月：不是派使者，是派十五万人
三、劝谏：从大臣到萧道成，全部反对
四、心态变量：从纳谏到自负
五、后果一：薛安都降魏，北魏要的不是一个人，是两个州
六、彭城战场：断粮道的老办法
七、天时：泗水结冰与冻掉脚趾的主帅
八、收尾：前后夹击与“仅以身免”
九、把它拆开：哪些是史事，哪些是解释
十、素材自己的笔法：反讽是怎么完成的
十一、空白与存疑（不补写）
十二、三条可迁移的读法
```

改后把“史事 / 解释 / 空白”拆成了独立小节；改前已经有这个意识，但主要放在“引语核查 / 三种解释 / 待查清单”里。

## 4. 出处结果差异

| 指标 | 改前 | 改后 |
| --- | --- | --- |
| 出处数 | 6 | 0 |
| 状态 | 6 候选 | `no_sources`，8 条 `待查` 跳过 |
| 耗时 / 成本 | 30.5s / ¥0.0421 | 7ms / 0 token |
| 直达原文 URL | 0 | 0（不生成假出处） |
| 错归书名/卷次 | 至少 3 条 | 0（因为不挂） |

改前那 6 条候选来自旧模型路径：十五万挂《宋书》、萧道成对白挂《宋书·明帝纪》、泗水冻死挂《资治通鉴》泰始二年，都是错的。改后不再猜，直接 `no_sources`。

## 5. 结论

- **同一篇没有史源的长稿**：改后不会比改前多出处，反而会显示 0 条；这是正确行为，因为它拒绝把现代转述冒充原文。
- **带史源的小素材**：改后能自动落成 1 条 found + 1 条 candidate（6ms / 0 token），见 `docs/trace-agent/runs/ai-note-claims-source/`。
- 改后的正文结构更适合以后接出处：它已经把“史事 / 解释 / 空白”拆开；下一步是让素材本身带书名/原文，或者人工把 `待查` 补成 `史载`。
