# 制作台溯源检索：方案与实测

> 状态：**已实现并通过真实视频复测**（2026-11-07）。
> 目标：把「速览与溯源」从“一次标题查询 + 一组结果核全篇”改成可解释、可复现、可续跑的多查询核查。
> 主检索渠道：**DeepSeek Search `/v1/tools/search`**；智谱/Tavily 保留为可选渠道。

## 1. 结论先行

1. 旧实现的问题不是 DeepSeek 不会搜，而是**检索粒度错了**：只查一次标题，却要求模型核对 18 条不同主张。标题查询能命中“选举结果”，但不可能覆盖“120 亿美元”“ 1180 万儿童”“400 万条含铅设施”。
2. 正确做法是**先抽可核查主张，再按主张生成检索词**；每条主张独立拿证据，最后只让模型在自己那条证据里判断。参考 SF 的 `traceExternal` 多查询 + 候选池思路，但不照搬它的网页正文抓取。
3. 首版选择 **DeepSeek Search 摘要**，不做网页正文抓取：摘要足够支持“有没有外部出处/来源是谁/引文是否在摘要里”，且不需要新 HTML 解析依赖、不会把单页 30 秒的抓取失败带进任务。
4. 引用必须**程序化校验**：`source` 必须是该主张证据里的 URL，`quote` 必须是证据摘要里的连续原文；模型编的引用一律降级为“未找到外部出处”。
5. 所有外部调用都进 checkpoint：主张抽取、每个检索词、每批核查都能续跑；改 pipeline 版本会使旧检查点失效。

## 2. 旧实现复盘

旧代码在 `pipeline.rs` 的 `trace` 步骤：

```text
query = title + " 事实核查"
hits = search(query, trace_max)
trace = model(原文 + hits) -> 所有主张
```

真实视频 `BV1fm476EEgh`（927 秒）的结果：

- 18 条主张，1 条外部可印证、17 条未找到外部出处；
- 唯一命中的是标题里的“民主党赢得中期选举”，来源为搜狐；
- 120 亿美元、1180 万儿童、400 万条含铅设施等数字全部落空。

这不是搜索渠道故障；是**一次标题查询**的信息容量不够。

## 3. 方案比较

| 方案 | 优点 | 问题 | 结论 |
| --- | --- | --- | --- |
| 一次标题查询（旧） | 快、便宜 | 只覆盖标题实体，数字/机构主张大量落空 | 淘汰 |
| 按主张多查询（本方案） | 每个数字/实体都有自己的查询；可解释 | 调用次数增加；查询质量依赖抽取模型 | **首版采用** |
| 多查询 + 抓网页正文（SF） | 能拿逐字引文，证据最强 | 需要 HTML/readability、抓取慢（p95 30s）、失败面大 | 后续增强 |
| 向量检索/embedding | 语义召回 | 不能替代“外部出处”；来源与引文仍要网页；索引成本高 | 不适用 |
| 直接让 chat 模型“联网” | 实现简单 | 不可控、无稳定来源、无法核验引文 | 不采用 |
| RSSHub/第三方聚合 | 无需自己搜 | 覆盖不全、延迟不可控、非官方 | 不作为主链路 |

## 4. 新流水线

```text
正文（速览稿）
  ↓ 1 次模型：抽取 3-20 条可核查主张，每条 1-2 个检索词
  ↓ 每条主张 × 每个检索词：DeepSeek Search（串行、180ms 间隔）
  ↓ URL 去重 + 权威度/词面覆盖排序，每条主张取 N 条证据
  ↓ 每 4 条主张一批：模型只在本条证据内判断
  ↓ source/quote 程序化校验
  溯源列表（claim / verdict / source / quote）
```

### 4.1 主张抽取

- Prompt：`trace_claims_system(max)`。
- 优先数字、日期、机构/人名归属、可验证事件/因果、法律政策事实；
- 跳过主观评价、反问、比喻、价值判断、预测；
- 每条给 1-2 个短检索词（含实体、年份或数字）；
- 只输出 `[{claim, queries}]`。
- 模型失败或返回空时，用正文中含数字/实体的行做启发式兜底，不会把整个溯源降级成一次标题查询。
- **程序化 grounding**：不允许模型把“标题联想到的站外知识”写成视频主张。每条 claim 必须通过：
  - 数字：claim 里的数字至少有一个在正文中出现；多个数字时至少 1/3 命中；
  - 中文 bigram：claim 的相邻二字组合至少 35% 出现在正文（短 claim 用 60%）；
  - 不满足就丢掉，不送去检索。
  这一条是实测后补的：第一版多查询跑出来 5 条“外部可印证”，但其中几条（越南战争、企鹅关税、疫苗、山火激光、大蒜）根本不在视频正文里，是抽取模型把标题联想成了外部事实。

### 4.2 检索

- 每个检索词单独调用检索接口；同一 query 通过 checkpoint 复用，不重复花钱。
- **查询语言**：涉及美国/外国机构、英文报告的主张必须一中一英两条查询。实测“美国卫生部2022 托育补贴 1180万儿童”中文查询拿不到 ASPE，而 `11.8 million children eligible child care subsidies HHS 2022` 第一条就是 `aspe.hhs.gov`。DeepSeek Search 不会自动把中文查询翻译成英文。
- 任务日志会打印每条主张实际使用的检索词，便于区分“没搜到”和“搜到了但核查没引用”。
- 串行 + 180ms 间隔；DeepSeek 账号级 5 QPS，串行比并发稳。
- 429/408 在检索层重试一次（600ms 后），其他错误直接记录并继续其他检索词。
- 每条主张合并多个检索词的结果，按 URL 去重。
- 每条主张最多保留 `trace_max` 条证据（默认 5）。

### 4.3 正文抓取

搜索摘要不够时，只对每条主张最靠前的来源做受控抓取：

- 第一轮每条主张抓 top1；第二轮在总预算内补 top2；
- 每次最多 12 个 URL，单页 60 秒超时，整轮抓取 180 秒硬上限；
- 单页最大 8MB；只允许 http/https；DNS 解析到回环/内网/链路本地地址直接拒绝；
- 最多跟随 5 次重定向，每次重定向都重新做 SSRF 检查；
- HTML 去 script/style/noscript/svg/template 后取 main/article/body 正文；
- PDF 用 `pdf-extract` 提取文本；扫描件没有文字时明确失败，不假装有引文；
- 抓到的正文追加到该来源的 content，仍以原搜索 URL 作为 source；quote 校验看到的是“摘要 + 正文”；
- 抓取按 URL hash 进 checkpoint，resume 不重复下载。

实测：ASPE 的 FY2022 PDF（567,722 B）从这台机器抓取并提取约 24 秒，能拿到
“In 2022, 11.8 million children were eligible…”。这也是为什么 ZCode 能查到、
而只读 Search 摘要的旧实现查不到。

### 4.4 排序

不单纯相信上游顺序，先做轻量排序：

- 权威度：政府/国际组织/教育机构 > 通讯社/主流媒体 > 一般站点 > 自媒体；
- 词面覆盖：主张中的中文 bigram 命中数 + 数字完全命中加分；
- 同分保持检索返回顺序；排序只决定“先给模型看哪几条”，不直接决定 verdict。

### 4.5 核查

- 每批 4 条主张，模型只拿到该批每条主张自己的证据。
- Prompt 要求：
  - `claim` 原样回填；
  - `source` 必须是证据中的完整 URL；
  - `quote` 必须是证据摘要中的连续原文，至少 8 字；
  - 没有证据写“未找到外部出处”；自媒体/论坛只能写“仅非权威来源”。
- 程序化校验：
  - source 不在该主张证据 URL 集合 → 清空；
  - quote 不在证据摘要中 → 清空；
  - 声称“外部可印证”但 source/quote 不成立 → 降级为“未找到外部出处”；
  - 不再让模型编造一条“看起来像”的引用。

### 4.6 入库与 UI

- 事实与证据写入事实库；笔记页事实侧栏展示来源，事实库可单独重新核验；
- 新生成笔记不再把整份 `## 溯源` 追加到 Markdown 末尾；旧笔记已有文本保留；
- 任务详情「溯源」tab 增加“查看来源 ↗”；
- 任务日志显示：抽取 N 条、检索成功/失败次数、去重候选数、核查进度。

## 5. 成本与时间预算

默认值：最多 10 条主张、每条最多 5 条来源、每主张 1-2 个检索词。

- 检索调用：最多 20 次；串行 + 180ms，通常十几秒；
- 模型调用：1 次主张抽取 + 最多 3 次核查（10 条 / 每批 4 条）；
- 相比旧版：多 1 次抽取 + 2 次核查 + 最多 19 次检索；换来的是每个数字/机构都有自己的查询。
- 用户可在新建向导调整「最多核查主张」和「每条主张最多来源」。

## 6. 失败与续跑

- 主张抽取失败：启发式兜底；日志 warning。
- 单条检索失败：记录 warning，继续其他检索词；全部失败才让 trace 步骤失败。
- 核查批次失败：任务失败，已完成的 claim 抽取/检索 checkpoint 保留；resume 只补未完成批次。
- 所有 checkpoint key：
  - `trace:claims`
  - `trace:search:<query hash>`
  - `trace:verify:<batch>`
- `PIPELINE_VERSION` 从 1 升到 2，旧溯源检查点不复用。

## 7. 验收

### 自动化

- `parse_claims`：限制条数、去重、无 query 的兜底；
- 启发式兜底：只保留含数字/实体信号的行；
- 排序：同等重叠时权威来源优先；
- 引用校验：伪造 URL 被替换/清空，伪造 quote 使 verdict 降级；
- `cargo test` 当前 97 passed / 2 ignored。

### 真实视频

- 用户指定：`BV1fm476EEgh`《民主党大胜中期选举，然后呢？》，927 秒。
- 旧版结果：18 条主张，1 条外部可印证、17 条未找到；
- 新版结果（加入 Fetch 后的最新一次）：10 条主张，**4 条外部可印证、6 条存在争议、0 条未找到**；
- 检索：20 次查询全部成功，91 条去重候选；抓取 12 次、成功 6 次，失败为 402/403/网络错误；
- 运行：约 6 分 15 秒；usage prompt 50,740（缓存 384）/ completion 36,919 / reasoning 30,031；
  音频 927s；估算 ¥0.21388；
- 用户截图中“1180 万儿童”那条：英文查询命中了 ASPE PDF，抓取 PDF 后拿到
  “An estimated 1.8 million children received subsidies…16%”；因为视频说的是“实际领取 120 万”，
  来源说 **180 万**，最终 verdict 是“存在争议”——这次不是未找到，而是找到了并指出视频数字不对；
- 中间一次多查询版本曾出现 5 条“外部可印证”，但其中越南战争、企鹅关税、疫苗、山火激光、大蒜等
  5 条根本不在视频正文；加 grounding 后这些被过滤；不同运行的主张抽取结果会变化，这是当前模型的
  非确定性。

## 8. 诚实边界

- 网页正文抓取只做静态 HTML/PDF；JS 渲染页、登录墙、反爬页、扫描版 PDF 仍可能抓不到。
- 只抓每条主张 top1/top2，总共最多 12 个 URL；更深页面不追。
- 单页 8MB、60 秒；ASPE 这类慢 PDF 单页可能占 20–30 秒，任务总时长会增加。
- 没有做 robots/站点条款判断；这是本地个人工具的单页抓取，不应当当作通用爬虫使用。
- 即使加了 grounding，数字/实体命中也只是“主张来自正文”，不代表主张本身正确。
- 权威度是域名白名单/经验分层，不是事实正确性；政府/主流媒体也会错。
- 排序里的词面覆盖只适用于中文/数字，英文主张主要靠上游排序。
- 主张抽取仍由模型完成；抽取漏掉的主张不会被核查。
- 查询语言依赖模型遵守“一中一英”要求；如果模型没给英文查询，涉及外文来源的主张仍可能漏掉。任务日志已记录实际检索词，可据此判断。
- DeepSeek Search 的摘要长度、结果数量、QPS 可能变化；429 只重试一次。
- 搜索成本没有进入 token usage；目前只统计 chat/ASR。
- 真实测试仍是一条视频、一个渠道，不能证明所有题材都提升。
- 最终 3/10 外部可印证不代表“应有 7 条未找到”：部分来源本身是自媒体/外媒转述，部分主张（如具体统计口径）确实难在公开摘要里找到；verdict 是证据判断，不是事实终审。

## 9. 后续增强

1. 接入 DeepSeek Fetch / readability，抓 top 1-2 个来源正文，做真正的逐字引文。
2. 增加“来源数量/站点数”展示，而不是只看 verdict。
3. 对“未找到”的主张再生成一轮改写 query（第二跳），但要有明确预算上限。
4. 搜索成本与延迟进入 usage/任务日志。
5. 对 ASR 重复段落做源级去重（本次真实视频暴露了重复四遍的问题）。
