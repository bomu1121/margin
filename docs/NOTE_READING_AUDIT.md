# 笔记阅读页走查与整改（2026-11-09）

> 范围：`/note/:id` 单篇阅读页本身（标题、署名、速览、正文、左右栏关系），不是新增的事实/史料页面。
> 结论先说：这次不是换皮，而是修了 7 处问题——标题被拆字、两条元信息重复且来源条在 1040 折成三行、笔记署名的是 UP 主而不是笔记本身、速览在窄页变成报纸双栏、正文列宽没有上限、窄窗标题不降级，以及「持久化栏宽」在窄窗被原样套用（1040 下正文只剩约 222px）。

带图报告：会话可视化目录的 `note-reading-audit.html`（改前/改后并排 + 三档 DOM 数据）；原图见下表。

## 1. 走查方法

- 运行最终构建（安装包 8,722,874 B），在打包窗口里用 CDP 截图 + DOM 计算样式。
- 视口三档：
  - 实际窗口 **1865×1271**（用户机器的真实窗口，用于确认超宽屏不拉长行宽）；
  - **1440×900**（常用桌面宽度，前后对照主图）；
  - **1040×760**（窄窗，检查左右栏与标题换行）。
- 同一篇笔记：`李世民当汉武帝的太子：机会不是没有，但确实不大`（2,461 字，3 条事实）。
- 只看「读起来是否顺」不够，所以每个问题都落一个可测值：标题视觉行数、署名行高度、速览列数、正文列宽、左右栏宽度。

## 2. 改前问题（带数字）

| # | 问题 | 实测/可见证据 | 为什么难看 |

| N3 | 速览是双栏 | 1040 下每条速览只剩约 13 个汉字一行，6 条挤成 3 行×2 列（`15-note-1040.png`） | 双栏本来用于宽页；窄页强行双栏，读起来像报纸小广告 |

## 3. 已改

### 3.1 标题按标点分块，不再拆字

`src/views/NoteView.vue:62` 把标题按 `：:，,、；;` 切成语义块，模板用 `span.note-title-part` 渲染；CSS 让每块 `white-space: nowrap`，整行用 flex 换行。

- 效果：1440 下稳定为两行——「李世民当汉武帝的太子：」/「机会不是没有，但确实不大」；1865 下同样是这两行，不会因为更宽就变成一行后再拆字。
- 字号：`clamp(30px, 2.7vw, 39px)`，最大 39px；容器 ≤760px 时降到 28px。
- 兜底：每个语义块 `min-width:0; white-space:normal`；能放下时仍按标点分块，放不下时块内换行。1040 下「伊朗和乌克兰都要为特朗普的失败负责」不再溢出到右栏被裁。

### 3.2 两条元信息合并为一行署名，去掉 UP 署名

改前是两条独立信息：`.meta`（作者 / 日期 / 完整 run id / 字数）和 `.prov-strip`（`ScribeFlow 生成` badge / 运行 id / prompt / 生成时间 / 查看来源与运行）。`note.runId` 和 `artifact.run.runId` 重复，badge 和按钮又都在说「来源」；而且第一条的「作者」是 UP 主，不是笔记作者。

现在只保留一条 `.note-byline`：

```text
2,461 字 · 原视频 ↗
```

- 删除 article 里的 UP 名、日期、完整 run id、`ScribeFlow 生成` badge、`运行 run_…`、prompt（如「速览版」）和生成时间。
- `原视频 ↗` 直接打开 B 站原视频（`artifact.source.url`）；按钮 `title` 带 UP 名和视频标题，正文里不再放作者。
- 日期、生成时间、run id、prompt 和 UP 名都在右栏「信息」和制作台任务里可查；信息里拆成「创建 / 发布 / 运行 / 生成」四行。
- 字数加千分位（`2,461 字`）；有标注时才追加 `N 条标注`；没有标签时不再渲染空 `.tags`。
- 视觉上从「两条带边框的元信息条」变成标题下一行 12px 的署名，高 20px；三档视口都没有横向溢出。

### 3.3 速览固定单栏

`.doc .takes ol { grid-template-columns: 1fr; }`。速览是「6 条判断」的连续阅读，不承担并排对比；宽页也不回到双栏。

### 3.4 正文列宽上限 860px

`.note-layout .doc { max-width: 860px; }`（`src/styles/panels.css:153`）。

- 1865 实际窗口：正文列宽 **860px**（DOM 实测），左右留白由页面居中吸收。
- 1440：正文 **622px**（左右栏仍按用户偏好 440/378，正文拿剩余空间）；容器 ≤760px，标题降到 28px，正文 17px / 行高 1.9。
- 1040：正文 **430px**，同样的 28px 标题与 17px 正文。

### 3.5 栏宽：偏好 vs 有效宽度

- 左栏持久化 `yebian.shell.sidebar.width`，但 `sidebarMaxWidth()` 在 ≤1180 视口把有效宽度压到 280；右栏同理压到 330。
- 不覆写用户存的 440/378；回到宽屏自动恢复。
- 结果：1040 下左栏 280 / 右栏 330 / 正文 430；1865 下左栏 440 / 右栏 378 / 正文 860。

### 3.6 侧栏改成 Obsidian 式单行，日期/UP 只留在「信息」

- 侧边栏收藏/树改成一行：图标 + 标题 + 可选标注数 badge；行高 `48px → 30px`，标题单行省略。
- 图标和文字光学对齐：`.note-row .tree-lead` 从 16px 改成 19px（等于标题行框 14px×1.35），SVG 从 14px 提到 16px，并整体上移 1px；星标按钮也上移 1px。原来 14px 图标在 16px 盒里显得又小又低。
- 日期不再出现在侧栏；阅读页署名也不再显示日期。
- 标签台结果和事实详情里的笔记组去掉 UP，保留日期/领域（它们是搜索结果，不是文件树）。
- 右栏「信息」保留完整来源：视频标题、`B站 · UP 名`、创建/发布日期、run id、生成时间，以及「打开原视频」「在制作台查看」。
- 笔记文件本身没有改格式：生成时 front matter 已经写入 `作者 / 原始链接 / 发布日期`，阅读页只是把「原视频」提到标题下、把 UP 和日期收进信息。
- 图谱仍把 UP 当作关系属性（UP 主节点），因为它承担连接语义，不是笔记署名；这一轮没有动图谱。

## 6. 诚实清单

- 只走查了这一篇 2,461 字的历史笔记；没有覆盖超长标题（>40 字）、纯英文标题、无标点标题的真实样本。
- 只截 1865 实际窗口 + 1440/1040 仿真；**没有验 900 宽、125%/150% 缩放、暗色模式、真实触屏**。
- 第一次 1040 复截图在容器查询生效前拍下，出现过假三行标题；已给 `tools/shot-page.mjs` 加 300ms 等布局并重截，最终数据以等待后的截图/DOM 为准。
- 「58 字/行 → 50 字/行」是按 17px 全角字估算，不是逐字断行统计；DOM 只实测了列宽 860。
- 标题按标点分块是启发式：冒号/逗号/顿号/分号都会切；如果标题本身在逗号处语义不该断，仍可能切得不理想。没有做语义断行。
- 署名行只留字数和「原视频」；日期、UP 名、run id、prompt、生成时间都在右栏「信息」和制作台。原视频是打开 B 站，不是内嵌播放：Tauri CSP 没有放 `frame-src`，B 站播放器依赖也不适合塞进阅读页。
- 侧栏删掉日期后，不能在列表里按日期扫读；日期仍在「信息」里。这是为了单行密度做的取舍。
- 侧栏、标签台、事实详情里的笔记组已去掉 UP；图谱仍把 UP 当关系属性（UP 主节点），因为它承担连接语义。这一轮没有动图谱。
- 左右栏收起、拖动、浮层滚动条属于上一批 `PANEL_INTERACTION.md` 的范围，这次只修了「窄窗有效宽度」和笔记页排版，没有重做那套交互。
- P2 未做：笔记右栏父事实「N 条子事实」badge、子事实父链接、事实库父子组。
