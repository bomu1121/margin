[7] Final DOM/SVG force graph (2026-11-04)
Supersedes the Canvas/d3 full-graph numbers in [3c] and [6]. The 1k/1.5k
d3-force benchmark is no longer relevant: the page now draws note cards and
tag pills as DOM, edges as SVG, and caps the graph.

Why changed:
- The old Canvas graph used glowing balls; in the native window it read as
  "light pollution", and clicking a note navigated away instead of showing
  the note's content.
- The 07-force prototype's DOM/SVG cards, focus/dim, side panel and explicit
  "打开笔记" action are the interaction target.

Implementation:
- Custom force layout (repulsion + edge springs + weak centering), not d3.
- Note cards are 148x44 and collide as axis-aligned rectangles; tag/person
  nodes collide as circles. Golden-angle spiral start; degree-scaled tag
  orbits; a final compaction + 24 collision-relaxation passes.
- Semantic zoom: below 78% notes are 14px dots (counter-scaled so they stay
  14px on screen) and only 7 major tags keep labels; at >=102% the dots become
  full cards. Click/search flies to 108%.
- Click focuses and opens a panel with meta, tags, up to 3 summary takes,
  related notes and an explicit "打开笔记" button. BFS path excludes the
  public source hub and hidden kinds.
- Default scope is the most recent 40 notes; "全部" switches to all, hard cap
  200. The HUD/breadcrumb state the scope.

Measurement method:
- Final release WebView2 156, 1456x939.
- performance.now() inside GraphView.build(), from start to after the first
  fit. Includes 320 force ticks, collision relaxation, DOM construction and
  node positioning. EXCLUDES CSS first-frame paint.
- Repeated with tools/measure-force-many.mjs; corpus generated by
  tools/make-bench-vault.mjs (42 topics, 28 people, 12 UP names, 4 domains,
  3 types, 3 sources, 8 periods).

2026-11-05 — file-level index split (supersedes the shadow-table swap above)

Layout:
  yebian.sqlite        annotations + settings
  yebian-index.sqlite  notes + notes_fts + index_meta
  Store opens the index DB and ATTACHes the user DB as `user`; reads use the
  index connection, annotations/settings use the attached user schema.
  The actor writes only the index DB.

  close the actor writer and Store read connection, rename staging over live
  with yebian-index.old as rollback, reopen/attach, then a stat catch-up.

  file and deletes .old; IndexService removes staging on startup.

2026-11-07 — P26: P2-02 断点续跑调研基线

- 点“重试”：又发 2 次请求（校对、加工都成功），最终 job 2M/2M、¥80。
- mock 实际收到 4 次、成功 3 次；按手动价应计 3M/3M = ¥120。
  结论：重试整条链路重复了已成功的校对，失败尝试的成本也完全不可见。

代码审计（未实现，不是实测行为）：
- MiMo ASR 分段在随机 temp 目录，任何一段失败会删除整个目录，已成功分段丢失。
- publish 先建 revision package，再 drain，再 finish；finish 前崩溃会再次 publish，
  next_revision 会生成新 revision；现有 ACK 只能防重复消费，不能防重复创建。
- job 未保存 vault/base URL/ASR 配置；切换库或改设置后重试可能写错库/复用错输入。
- fail() 不接收已累积 usage。

设计结论：见 docs/RESUME_DESIGN.md。检查点按外部调用/ASR 分段落 SQLite，
run 从顶部重放并按 input_hash 命中；publish 按 noteId + runId + body hash 认领；
job 绑定 vault 并快照非密钥配置；失败时写入已知 usage。
未实现；ASR/publish 的重复成本目前是代码审计结论，计划用失败注入矩阵验收。

2026-11-10 — P76: 浮层滚动条不再被程序化滚动闪出

现象：页面刚切到一个可滚动容器，或有滚动条出现的瞬间，浮层会先出现再按隐藏逻辑消失，产生抖动。实测切笔记时 `doc-scroll.scrollTop` 从 600 归零，触发 `scroll`，浮层 `is-visible`。

修复：
- 增加用户意图门控：`wheel` / `touchmove` / PageUp/PageDown/方向键/Home/End/空格 在 400ms 内发生过，`onScroll` 才显示；否则直接忽略。

- 改为 `isEligible`（纵向、无横向）而不是「当前可滚动」决定 `yb-scroll`：收起时也保留类；MutationObserver 回调先同步 `markCandidates()`，再 debounce scan，DOM 变到可滚动之前原生条已经隐藏。`nearEdge` 仍要求 `canAttach`，不会给不可滚动容器显示浮层。
