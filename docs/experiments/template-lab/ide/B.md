# 插件只是过渡：作者为什么已经很久没打开 IntelliJ IDE

## 一句话结论

作者的判断是：AI coding 插件受宿主 IDE 能力限制，只是过渡形态，真正的工作台要围绕 agent 编排重建，但这不意味着 JetBrains 会被淘汰。

## 速览

- 作者已经想不起上次打开 IntelliJ IDE 是什么时候，周围同事也不再靠 IDE 插件用 AI。
- 插件的天花板在于只能拿到宿主 IDE 给的能力，且宿主自己做 agent 时会与插件直接竞争。
- 传统 IDE 的重心是代码编辑与调试验证，现在的重心是 agent 编排、任务管理和需求约束，插件补不上这个差距。
- 所以不少公司选择做自己的 AI native IDE，代码仍可编辑，但工作台重心从编辑上抽离。
- 单从功能上做 IDE 门槛不高，基于 MIT 协议的 VS Code 就能快速搭一个；JetBrains 仍有工程化壁垒，但难再现赢家通吃。

## AI coding 插件的上限由宿主 IDE 决定

作者认为，靠装插件来用 AI 的方式正在退场，原因不是插件做得不好，而是它的能力边界不由自己决定。他的原话是「这些 AI 的插件，它的能力是有边界的，它会受制于宿主 IDE 给它提供的这个能力」——插件能读什么、能改什么，取决于宿主愿意开放多少。

第二个理由是竞争关系：「哪一天宿主 IDE 一旦开发了自己的 agent，也会跟这些 AI 插件直接形成竞争关系」。也就是说插件的位置本身不稳定，宿主一旦自己下场，插件就从补充变成对手。

限定条件是作者的口径只代表他观察到的范围：他说「我周围的同事已经不通过这种方式去使用了」，同时也承认「不排除现在还有一些同学依旧通过这种方式在使用 AI」。这是一份身边样本的判断，不是行业统计。

## 传统 IDE 和现在的开发重心已经错位

作者把两边的工作方式做了对照：传统 IDE「整个任务开发的核心关注点都是在于这个代码的编辑，还有开发完的调试、验证这些功能」；而现在的开发模式「核心在于这个 agent 的编排、任务管理、需求约束这些最根本的工作方式」。

错位的结论因此很直接——「就导致这种传统的 IDE 其实已经跟不上时代了」。这里作者强调的不是功能缺失，而是关注点放错了地方：编辑器和调试器再强，也不是今天任务推进的主轴。

作者还特意堵住了“出个插件就行”这条路：「这些东西不是开发一个插件就能解决的」。这句话是他整期论证的枢纽，也解释了他为什么把话题从插件拉到 IDE 本身。

## 公司自建 AI native IDE 是为了重构工作流

作者认为，既然插件解决不了，就只能动工作台本身，这就是「很多公司都需要去开发自己的 AI native IDE」的来由——目标是「去重构了整个 AI 开发的工作流」，而不是再做一个更好的编辑器。

重构之后并不是不能写代码，而是重心变了：「它们仍然是允许编辑代码，但是整个工作台的重心已经从代码编辑上给抽离出来了」。编辑能力被保留，但不再是组织工作的中心。

这里需要留意措辞的强弱：作者用的是“很多公司都需要”，讲的是趋势与必要性，素材里没有给出任何公司名称、产品名称或落地效果，所以这仍然是他的观察与主张，不是已经验证的行业结论。

## 做一个 IDE 本身已经没有太多门槛

作者并不认为 IDE 这个形态本身有多难复制。他的判断是「现在只是从功能上开发一个 IDE，其实并没有太多的门槛」，理由是可以「完全可以基于这种开源的、MIT 协议的 VS Code 去快速地构建一个新的 IDE 出来」。

这条依据同时解释了两件事：为什么从功能上复制一个 IDE 不再困难，以及为什么先发者的位置不再稳固。门槛更像是从“造编辑器”转到了“把工作流重新组织好”。

不过作者说的是“从功能上”没有太多门槛，范围限定在功能实现；工作流设计、工程化积累这些他并没有一并归入“无门槛”，后面谈 JetBrains 时也正好把工程化单列了出来。

## JetBrains 不会被淘汰，但赢家通吃难再维持

作者对“JetBrains 会不会被淘汰”的回答是否定的：「我认为应该不会啊」，理由是「JetBrains 它其实还是有它的这个工程化的壁垒的」。

但他把壁垒和地位拆开看：「只是它应该不会像以前那种赢家通吃的状态」。也就是说工程化优势还在，只是位置不再是唯一的入口。

这一节是全篇最弱的一句判断——作者用了“应该不会”，是推测语气，素材里没有给出 JetBrains 的营收、用户量或产品动作作为支撑。他对整件事的定位也是「插件只是一个过渡状态，这就是我对于 AI IDE 的看法」，明确标成了个人看法。

## 关键数字与专名

- **IntelliJ IDE**（产品）：作者已经想不起上次打开它的时间，作为传统 IDE 的代表被反复提到。
- **JetBrains**（公司）：作者认为它有工程化壁垒，但难再维持赢家通吃。
- **AI coding 插件**（产品形态）：作者判断其能力受宿主 IDE 限制，且会与宿主自研 agent 竞争。
- **agent 编排、任务管理、需求约束**（工作方式）：作者用来描述现在开发模式核心的三项。
- **AI native IDE**（概念）：作者所指的原生 AI 开发环境，重心从代码编辑抽离。
- **VS Code**（开源项目）：作者称其开源且为 MIT 协议，可用于快速构建新 IDE。
- **Bilibili 社区**（平台）：作者称本期文字版整理在那里，链接在视频简介中。

## 不确定与未展开

- 作者说“忘了上次打开 IntelliJ IDE 是什么时候”，具体隔了多久、是否彻底停用，素材未说明。
- 周围同事现在具体在用什么 AI 工作台，素材没有点名任何产品或公司；自建 AI native IDE 的公司也没有举例。
- JetBrains 的“工程化壁垒”具体指哪些能力，作者只给了这个词，没有展开论证。
