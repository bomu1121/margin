# 从 IntelliJ 到 AI 工作台：插件只是过渡，重心已转向 agent 编排

## 一句话结论

作者认为传统 IDE 和挂在它上面的 AI 插件都只是旧范式，真正的 AI 开发环境要重构成以 agent 编排、任务管理、需求约束为重心的工作台，而 JetBrains 靠工程化壁垒仍能留下，只是不再赢家通吃。

## 速览

- 作者已经很久没打开 IntelliJ，并把身边的同事当作"不再用插件写 AI 代码"的证据。
- AI 插件的能力上限由宿主 IDE 决定，且宿主自研 agent 后必然与插件正面竞争。
- 开发的核心关注点已从代码编辑、调试、验证，转向 agent 编排、任务管理与需求约束。
- AI native IDE 的做法是重新分配工作台重心，不是取消代码编辑。
- 单独做一个 IDE 的功能门槛已经很低，用 MIT 协议的 VS Code 就能快速起一个新 IDE。

## 作者的工作流已经离开传统 IDE，插件式 AI 是被先放弃的一环

节目开场给的第一个信号是个人使用习惯的变化："我已经忘了我上次打开 IntelliJ IDE 这个工具是什么时候了"。它没有给数据，只有一个自述和一句反问——现在还有多少人在用这种传统 IDE 工具。紧接着作者补充，很多同学最早接触 AI 开发，都是从装一个 AI coding 插件开始，让它在项目里做补全、批量改文件。

但作者强调，这个入口形态在他周围已经失效："我周围的同事已经不通过这种方式去使用了"。就证据强度而言，这一节全靠作者的个人观察，没有样本量、时间范围或团队规模（素材未说明），所以它更接近一份从业者的体感报告，而不是行业统计。

## 插件的天花板来自宿主：能力有边界，还会被宿主的 agent 反噬

作者对插件路线的批评有两层。第一层是能力边界——插件的功能只能建立在宿主 IDE 愿意开放的能力之上，"它会受制于宿主 IDE 给它提供的这个能力"，因此插件能做到什么，本质上是宿主决定的。

第二层是竞争关系：一旦宿主 IDE 自己做了 agent，插件立刻从补位者变成对手，"哪一天宿主 IDE 一旦开发了自己的 agent，也会跟这些 AI 插件直接形成竞争关系"。这构成了作者判断"插件只是一个过渡状态"的主要依据——不是插件做得不够好，而是它在生态位上是临时的。

## 开发重心从代码编辑迁移到 agent 编排，这个缺口插件补不上

作者把两代工具的核心关注点做了正面对比：传统 IDE 的重心是老模式下的代码编辑，以及开发完的调试、验证；而现在的开发模式，"核心在于这个 agent 的编排、任务管理、需求约束这些最根本的工作方式"。

正因为差异发生在工作方式这一层，而不是功能清单这一层，作者给出的结论很直接："这些东西不是开发一个插件就能解决的"。反过来说，这也是他解释为什么许多公司要自己做 AI native IDE 的原因——不是因为插件不好用，而是插件的形态装不下这套工作流。

## AI native IDE 重构的是工作流，代码编辑并没有被取消

容易被误读的一点是"新 IDE 不再写代码"。作者的说法更克制：新的原生 AI 开发环境"仍然是允许编辑代码，但是整个工作台的重心已经从代码编辑上给抽离出来了"。抽离的是重心，不是编辑器这个组件。

这也解释了作者为何把"重构整个 AI 开发的工作流"当作关键动作：改的是任务从哪里发起、约束在哪里定义、谁来推进执行，编辑器退回到它擅长的位置。作者没有点名任何具体的 AI native IDE 产品作为例证（素材未说明），这一节停留在方法论层面。

## JetBrains 不会被淘汰，但"造 IDE"的门槛下降会终结赢家通吃

面对"JetBrains 以后是不是会被淘汰"这个问题，作者的答案是"我认为应该不会"，理由是"JetBrains 它其实还是有它的这个工程化的壁垒的"。他没有展开这层壁垒具体指什么（素材未说明），只把它当作 JetBrains 的护城河。

但护城河不等于垄断。作者的另一半判断是，如今"只是从功能上开发一个 IDE，其实并没有太多的门槛"，因为"完全可以基于这种开源的、MIT 协议的 VS Code 去快速地构建一个新的 IDE 出来"。门槛降低意味着新入局者变多，于是格局从赢家通吃转向多家并存——JetBrains 留在牌桌上，只是不再独占。

## 关键数字与专名

- **IntelliJ IDE**（产品）：作者用来标记自己工作流断点的工具，并称已忘记上次打开的时间。
- **JetBrains**（公司）：作者判断它不会被淘汰，凭的是"工程化的壁垒"，但不再赢家通吃。
- **VS Code**（产品）：作者称其开源、采用 MIT 协议，可据此快速构建新的 IDE。
- **AI coding 插件**（产品形态）：最早接触 AI 开发的入口，能做补全与多文件修改，作者判定为"过渡状态"。
- **AI native IDE**（概念）：作者定义的原生 AI 开发环境，允许编辑代码但重心已抽离。
- **agent 编排 / 任务管理 / 需求约束**（概念）：作者认为构成当下开发模式核心的三件事。
