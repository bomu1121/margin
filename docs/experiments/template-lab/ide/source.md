最近我突然意识到一件事情，我已经忘了我上次打开 IntelliJ IDE 这个工具是什么时候了。我不知道现在还有多少同学在使用这种传统的 IDE 工具啊。我先声明一下啊，这期没有任何广告，完全就是我对以后 AI 工作台的一些看法。很多同学最开始接触 AI 开发都是通过安装这种 AI coding 的插件，能够帮你去做一些补全、修改很多文件。不排除现在还有一些同学依旧通过这种方式在使用 AI。反正我观察下来，我周围的同事已经不通过这种方式去使用了。因为这种方式其实有一个很大的限制，就是这些 AI 的插件，它的能力是有边界的，它会受制于宿主 IDE 给它提供的这个能力。而且哪一天宿主 IDE 一旦开发了自己的 agent，也会跟这些 AI 插件直接形成竞争关系。另外就是传统的这种 IDE 啊，它的这个核心还是在以前的这种老模式，整个任务开发的核心关注点都是在于这个代码的编辑，还有开发完的调试、验证这些功能。那现在的开发模式呢，核心在于这个 agent 的编排、任务管理、需求约束这些最根本的工作方式，就导致这种传统的 IDE 其实已经跟不上时代了。这些东西不是开发一个插件就能解决的，
能不能去重构呢？这就是为什么很多公司都需要去开发自己的 AI native IDE，也就是这种所谓的原生的 AI 开发环境，去重构了整个 AI 开发的工作流。它们仍然是允许编辑代码，但是整个工作台的重心已经从代码编辑上给抽离出来了。那像 JetBrains 这种工具啊，以后是不是就会被淘汰了？我认为应该不会啊。JetBrains 它其实还是有它的这个工程化的壁垒的，只是它应该不会像以前那种赢家通吃的状态，因为现在只是从功能上开发一个 IDE，其实并没有太多的门槛，完全可以基于这种开源的、MIT 协议的 VS Code 去快速地构建一个新的 IDE 出来。插件只是一个过渡状态，这就是我对于 AI IDE 的看法。大家现在都用了什么 AI 工作台呢？我也非常好奇啊，也欢迎大家在评论区来分享一下。这期视频的文字版我也整理在我的 Bilibili 社区里面，大家感兴趣也可以在视频简介中获取这个链接。这期就分享到这里，谢谢大家观看，拜拜。
