# 插件只是过渡态：AI 编程的重心正从「编辑代码」移向「编排 agent」

## 一句话结论
作者判断：AI 编程插件只是过渡形态，传统 IDE 已经跟不上以 agent 编排为核心的新工作流，出路是重构出重心不在代码编辑上的 AI 原生开发环境——但 JetBrains 不会因此被淘汰，只是不再赢家通吃。

## 速览
- 作者已经很久没打开 IntelliJ IDEA，插件式 AI 编程在他身边基本退场。
- AI 插件的能力上限由宿主 IDE 决定，宿主自建 agent 后还会与插件正面竞争。
- 传统 IDE 的重心是代码编辑与调试验证，新工作流的重心是 agent 编排、任务管理与需求约束。
- 这个落差不是加一个插件能补上的，所以要重构整个工作流，也就是 AI 原生 IDE。
- JetBrains 有工程化壁垒，不会被淘汰，但赢家通吃的格局结束了。
- 从功能上做一个 IDE 门槛已不高，可以基于开源的 VS Code 快速搭出来。

## 作者是从自己的使用习惯变化推出这个结论的

这不是一份行业数据报告，而是一次个人盘点。他开场说自己突然意识到，已经忘了上次打开 IntelliJ IDE 是什么时候；紧接着承认不知道现在还有多少同学在用传统 IDE，并且明说这期没有广告，只是他对以后 AI 工作台的看法。

他给的观察样本很具体：很多同学最初接触 AI 开发，都是装一个 AI coding 插件来补全、改文件；但按他的观察，周围的同事已经不这么用了。

限定条件在他自己嘴里：「我观察下来」「我周围的同事」这类说法，说明这是圈层经验而非统计结论；他反问观众现在用什么工作台，也等于承认这点的答案还开放。

## 插件的天花板不在自己手里，而在宿主 IDE 手里

作者认为插件路线的根本问题不是能力暂时不够，而是能力边界由别人划定。原话是这些插件「受制于宿主 IDE 给它提供的这个能力」，能被调用什么，取决于宿主愿意开放什么。

他还补了一层竞争判断：哪一天宿主 IDE 开发了自己的 agent，就会跟这些插件直接形成竞争关系。这条比「能力不够」更致命——插件不是被同类淘汰，而是被自己赖以生存的平台收编。

需要注意的是，视频没有举出任何具体的 API 受限案例，也没有讨论插件厂商是否可能脱离宿主、转向独立形态。所以这更像结构性推断，而非可验证的现场证据。

## 真正的位移发生在工作重心，而不是编辑器换皮

节目判断：AI 原生 IDE 的意义不在界面好不好看，而在把重心从代码编辑这个环节抽离出去。旧模式的核心关注点是代码编辑，以及开发完之后的调试、验证；现在开发模式的核心，变成了 agent 的编排、任务管理、需求约束这些「最根本的工作方式」。

他强调 AI native IDE 仍然允许编辑代码——也就是说代码编辑没有被废除，只是不再是工作台的中心。

## 作者认为「再写个插件」补不上，因为差距落在工作方式层

把插件判为过渡态，他的理由是差距发生在工作方式层，而不是功能清单层。原句是「这些东西不是开发一个插件就能解决的」，正因为此，很多公司才需要开发自己的 AI native IDE，去重构整个 AI 开发的工作流。

这条推理链是：老 IDE 的架构服务于「编辑—调试—验证」，而新流程要求把 agent 编排和任务约束放在前面；架构的默认假设换了，加装模块就失效。

反过来说，视频没有拆开论证为什么插件层一定补不上——是界面自由度、上下文权限，还是任务调度做不了，都没说，这一步属于断言式判断。

## JetBrains 不会出局，但赢家通吃的局面结束了

他明确回答了「JetBrains 以后会不会被淘汰」：应该不会，因为 JetBrains 还是有它的工程化壁垒。节目并不唱衰老牌 IDE，只是把它从「唯一入口」降级为「仍然有价值的一类工具」。

但他同时削掉了它的垄断地位：不会像以前那种赢家通吃的状态。理由是造 IDE 的门槛下降了——现在只是从功能上开发一个 IDE，其实并没有太多门槛。

这两句放在一起才是完整判断：壁垒仍然值钱，但值钱的方式从「锁住所有人」变成「留住需要它的人」。至于「工程化壁垒」具体指什么，视频只用了一个词，没有展开。

## 门槛下降只发生在「功能」这一层

支撑上一节的技术依据很朴素：完全可以基于开源的、MIT 协议的 VS Code，快速地构建一个新的 IDE 出来。在作者看来，「做出一个能用的 IDE」和「守住工程化优势」已经是两件事。

这也解释了他为什么把插件称为过渡状态——中间形态存在的理由，是重构成本还高；一旦底座可以低成本复用，重构就划算，插件这一步就被跳过了。

限定也很明显：他只说了这条捷径省掉什么，没说它要付什么代价，比如长期维护、生态与调试深度。

## 关键数字与专名
- **IntelliJ IDEA**（产品）：作者提到自己已想不起上次打开它是什么时候，用作传统 IDE 使用频率下滑的引子。
- **JetBrains**（公司）：作者认为它有工程化壁垒、不会被淘汰，但不再赢家通吃。
- **VS Code**（产品）：被举例为可基于开源、MIT 协议快速构建新 IDE 的底座。
- **AI native IDE**（产品类别）：节目用来指重构过 AI 开发工作流、重心已从代码编辑抽离的原生开发环境。
- **AI coding 插件**（产品形态）：视频判定的过渡状态，能力受宿主 IDE 约束。
- **agent 编排 / 任务管理 / 需求约束**（概念）：作者概括的新开发模式三大重心。

## 不确定与未展开
- 作者始终没说他自己现在用什么 AI 工作台，只在结尾反问观众，最关键的使用样本是缺的。
- 「MIT 协议的 VS Code」具体指哪一层、以什么方式复用，视频没说明，需要外部核查。
- 「插件受制于宿主 IDE 的能力」没有任何具体受限实例，也没讨论插件能否脱离宿主独立演进。
- 「工程化壁垒」只出现了一个词，具体落在哪些工程能力上，视频没有展开。
