# 全局配色调研与重做方向（2026-11-17）

> 目标：回答“为什么现在的土黄 + 淡蓝看起来脏”，并给出一套可落地的全局配色逻辑。本文保留调研、审计和 demo；四套主题与设置页的最终落地记录见 [`THEMES.md`](THEMES.md)。

## 0. 结论

1. 现在的问题不是某个 hex 不够好看，而是**三种色彩语言同时承担主色**：米黄承担大面积表面，金色承担“历史/档案”，蓝色承担链接和选中。三种语言没有共同的温度与彩度，叠在一起就会显得旧、脏、互相抢。
2. 成熟产品的一条共同规则是：**中性表面 + 一个主色 + 只用于状态的状态色**。金色在 GitHub/Ant Design 里只用于 attention/warning，不作为“历史”分类色。
3. 现有配色在 WCAG 上全部合格（浅色最低 5.26:1，暗色最低 5.33:1）。这正是问题：**对比度只能证明“能读”，不能证明“协调”**。继续拿 4.5:1 为它辩护是错误的方向。
4. 我建议先看 **A 中性工具**；如果仍想保留纸感，选 **B 暖灰编辑**，但必须去掉金色；**C 石墨靛蓝**适合更强的产品识别和暗色；**D 暖灰陶土**是“连蓝色也不要”的实验。

## 1. 现有配色审计

### 1.1 当前 token

| 角色 | 浅色 | 暗色 |
| --- | --- | --- |
| 画布 / 顶栏 `paper` | `#f4f1e8` | `#0c0b09` |
| 阅读面 / 卡片 `surface` | `#fffdf8` | `#211d16` |
| 左右栏 `rail` | `#f4f1e8`（panels 覆盖） | `#1a1712` |
| 正文 `ink` | `#1b1813` | `#eee9df` |
| 主色 `blue` | `#1f4fd8` | `#7aa2ff` |
| 历史/强调 `gold` | `#8a5d0c` | `#e3ad4f` |

### 1.2 使用计数

用 `grep` 统计 `src/styles`、`src/views`、`src/components` 里的 token 出现次数：

| token | 次数 | 主要用途 |
| --- | ---: | --- |
| `--blue` | 371 | 链接、选中、焦点、未读点、标注、按钮 hover |
| `--gold` | 123 | 历史域、事实争议、标注“存疑”、图谱节点、警告 |
| `--green` | 64 | 成功、已核验 |
| `--red` | 92 | 错误、危险 |

`--gold` 同时承担“历史分类”和“警告”两种语义，结果是：

- 历史事实的金色徽标和真正的冲突/警告共用一套颜色，警告失去稀缺性；
- 米黄纸面 + 金色徽标让界面发旧；
- 蓝色又负责所有交互，冷色的蓝点和暖色的金在同一个画面里没有共同语言；
- 浅色选中态用 `--blue-soft` 大面积铺底，进一步放大了“淡蓝 + 土黄”的冲突。

### 1.3 对比度不是问题

`tools/color-contrast.mjs` 对当前 token 的计算结果：

| 配对 | 浅色 | 暗色 |
| --- | ---: | ---: |
| 正文 / 阅读面 | 17.41 | 13.86 |
| 次级文字 / 阅读面 | 8.60 | 7.72 |
| 弱化文字 / 左右栏 | 5.48 | 5.68 |
| 主色 / 阅读面 | 6.52 | 6.74 |
| 金色 / 阅读面 | 5.66 | 8.27 |

全部 ≥4.5:1。这说明“难看”不是可读性 bug，而是色彩关系错误；继续调 4.5 的边界没有意义。

## 2. 调研

### 2.1 方法

- 优先看官方设计系统文档：GitHub Primer、Ant Design、Material 3、Radix Colors、Tailwind、Obsidian、Stripe、Apple HIG、Atlassian。
- 产品 UI（Linear、Notion、Craft、Bear、Raycast）没有完整公开 token，只把公开资料/观察值当作**方向参考**，不当作权威规范。
- 所有候选色板用同一套 WCAG 公式计算，脚本在 `tools/color-contrast.mjs`；色板 demo 在对话内，可切 A–D 和明暗。

### 2.2 对照矩阵

| 产品/系统 | 表面 | 文本 | 主色 | 可以借什么 |
| --- | --- | --- | --- | --- |
| **GitHub Primer** | 白 `#ffffff` / 浅灰 `#f6f8fa` | `#1f2328` | 蓝 `#0969da` | 中性表面 + 单一蓝；金色 `#9a6700` 只用于 attention |
| **Ant Design** | 页面 `#f5f5f5` / 容器 `#ffffff` | `#1f1f1f` | 蓝 `#1677ff` | 三层 surface；primary 只给每屏最重要的动作；功能色只给状态 |
| **Vercel Geist** | 白 / `#fafafa` | `#171717` | 蓝 `#006bff` | 纯中性 + 极少量强调；暗色近黑但不用棕色 |
| **Linear** | `#08090a` / `#191a1b` | `#f7f8f8` | 靛蓝 `#5e6ad2` / `#7170ff` | 用亮度层级而不是色相分层；靛蓝只给交互 |
| **Stripe** | 白 / `#f6f9fc` | 深海军蓝 `#0a2540` | 靛蓝 `#635bff` | 冷色中性统一；强调色只做品牌/行动 |
| **Notion** | 白 / 暖灰 `#f7f6f3` | 暖近黑 `#37352f` | 蓝 `#2383e2` | 暖中性可以成立，但彩度必须低，且不能再用金色当第二主色 |
| **Craft** | 暖白 `#fcf9f7` / 白 | 近黑 `#030302` | 蓝 `#0087ff` | 暖白可以很轻，不需要米黄 |
| **Bear** | 白 / 冷灰 `#f3f5f7` | 石墨 `#444444` | 珊瑚红 `#dd4c4f` | 蓝色不是必需品；非蓝主色可以很克制 |
| **Obsidian** | 白 / 灰阶 `#f6f6f6` | 近黑 `#222222` | 紫（HSL 默认） | 中性灰阶 + 用户可换主色；不要让分类色抢交互色 |
| **Raycast** | 近黑 `#07080a` / `#101111` | `#f9f9f9` | 红 `#ff6363` + 蓝信息色 | 暗色中性可以很干净；品牌色只做标点，不做大面积 |
| **Material 3** | 由 neutral tonal palette 生成 surface 角色 | on-surface | primary 角色 | surface/on-surface/primary 是角色，不是固定色；明暗各一套 role mapping |
| **Radix Colors** | 12 阶：1–2 背景、3–5 组件、6–8 边框、9–10 实底、11–12 文字 | 11/12 | 单一 scale 的 9/10 | 每个色阶按用途分步，不靠“一个蓝走天下” |

### 2.3 从成熟项目提炼出的 6 条规律

1. **一个主色，不是两个。** GitHub、Ant、Vercel、Linear、Stripe 都只有一个主交互色；金/黄/红/绿只在状态里出现。
2. **金色不是分类色。** GitHub 的 `#9a6700` 在 attention token 下，Ant 的功能色只给 status；没有成熟系统用金色表示“历史”这种内容分类。
3. **暖中性可以，但必须低彩度。** Notion 的 `#f7f6f3` 和 Craft 的 `#fcf9f7` 都接近白，不是 `#f4f1e8` 这种明显发黄的纸面。
4. **层级靠亮度，不靠色相。** Linear/GitHub 的 surface 逐级变亮或变暗；不是“正文暖、侧栏也暖、卡片再暖”。
5. **暗色用中性炭黑，不用棕黑。** GitHub `#0d1117`、Linear `#08090a`、Vercel `#000/#1a1a1a` 都没有暖棕偏色。
6. **对比度是底线，不是设计目标。** Notion 的蓝 `#2383e2` 在纯白上只有 3.88:1，连 AA 都不到；成熟产品也会为了品牌牺牲一点，但我们要用更深的蓝 `#1668c4` 保证小字。这个例子正说明：不能拿“通过对比度”当配色正确。

### 2.4 不能直接照搬的地方

- Notion 的暖灰 + 蓝是成功的，但它的蓝色并不满足小字 AA；直接抄会重蹈“好看但不可读”。
- Vercel 的纯白/纯黑很锐利，但我们的阅读页面积大，纯白会刺眼；用 `#ffffff` 阅读面 + `#f6f8fa` 画布即可。
- Bear 的珊瑚红很有辨识度，但会和错误红混淆；如果选 D，必须把 danger 做成更深的红，并且只在小面积使用。

## 3. 四套方向

四套都遵守同一组角色规则；差别只在“中性色的温度”和“主色是谁”。

| 方向 | 参考 | 浅色表面 | 主色 | 暗色 | 适合 |
| --- | --- | --- | --- | --- | --- |
| **A 中性工具** | GitHub / Ant / Vercel | 冷灰白 `#f6f8fa` + 白 | 钴蓝 `#0969da` | 中性炭黑 `#0d1117` | 最稳，最像现代工具 |
| **B 暖灰编辑** | Notion / Craft | 低彩度暖灰 `#f7f7f5` + 白 | 深蓝 `#1668c4` | 暖中性 `#191919` | 想保留纸感，但不要金色 |
| **C 石墨靛蓝** | Linear / Stripe | 冷灰 `#f7f8fa` + 白 | 靛蓝 `#4f5bc4` | 石墨黑 `#08090a` | 更强的产品识别，暗色最好 |
| **D 暖灰陶土** | Bear / Craft | 暖灰 `#f7f6f3` + 白 | 陶土红 `#b4432f` | 暖炭黑 `#171614` | 连蓝色也不想要 |

### A · 中性工具（推荐先看）

- 浅色：`#f6f8fa` 画布 / `#ffffff` 阅读面 / `#eef1f4` 侧栏 / `#1f2328` 正文 / `#0969da` 主色
- 暗色：`#0d1117` / `#161b22` / `#10151c` / `#e6edf3` / `#4493f8`
- 关键：主色只出现在链接、当前项、焦点；选中行用中性 `#e8edf3` + 2px 蓝左线，不做淡蓝铺底。

### B · 暖灰编辑

- 浅色：`#f7f7f5` / `#ffffff` / `#f1f1ee` / `#2f2f2b` / `#1668c4`
- 暗色：`#191919` / `#202020` / `#1c1c1c` / `#e9e9e6` / `#5aa7f0`
- 关键：保留“纸感”的只有低彩度暖灰，不再用米黄、不再用金色；蓝色加深到 4.75:1。

### C · 石墨靛蓝

- 浅色：`#f7f8fa` / `#ffffff` / `#eef0f4` / `#16181d` / `#4f5bc4`
- 暗色：`#08090a` / `#101113` / `#0d0e10` / `#f7f8f8` / `#7170ff`
- 关键：暗色是主角；靛蓝比默认蓝更有品牌感，但仍然只做交互。

### D · 暖灰陶土

- 浅色：`#f7f6f3` / `#ffffff` / `#f1efeb` / `#2e2c29` / `#b4432f`
- 暗色：`#171614` / `#201e1b` / `#1a1917` / `#eee9e1` / `#e07a5f`
- 关键：完全没有蓝色；陶土红承担主色，危险红必须更深并与主色分开。适合实验，不作为默认推荐。

## 4. 对比度

`node tools/color-contrast.mjs`，全部候选的最低值都 ≥4.5:1：

| 方向 | 浅色 正文/阅读面 | 浅色 弱化/侧栏 | 浅色 主色/阅读面 | 暗色 正文/阅读面 | 暗色 弱化/侧栏 | 暗色 主色/阅读面 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 现状 | 17.41 | 5.48 | 6.52 | 13.86 | 5.68 | 6.74 |
| A 中性工具 | 15.80 | 4.81 | 5.19 | 14.64 | 5.96 | 5.58 |
| B 暖灰编辑 | 13.44 | 4.80 | 4.75 | 13.39 | 5.51 | 6.38 |
| C 石墨靛蓝 | 17.76 | 4.79 | 5.79 | 17.76 | 5.94 | 4.92 |
| D 暖灰陶土 | 13.92 | 4.61 | 5.55 | 13.76 | 5.08 | 5.64 |

补充：B 的 Notion 原始蓝 `#2383e2` 在纯白上只有 **3.88:1**，所以候选把蓝加深到 `#1668c4`；这是“参考产品”与“可读性”之间的取舍，不是照抄。

## 5. 落地时必须遵守的规则

1. **一套中性表面 + 一个主色。** 不再增加第二个装饰性主色；金色只在 warning 里出现。
2. **主色只做小面积。** 链接、当前项、焦点、未读点、2px 左线；不做大块淡蓝底。
3. **选中态用中性底色。** `--selected` 是中性 surface 的下一档亮度，不是 accent-soft。
4. **历史不是颜色。** 历史域用中性 chip/文字；只有真正的冲突、超限、错误才用 warning/danger。
5. **状态色必须带文字或形状。** 不允许只靠 6px 色点表达未读/冲突。
6. **暗色用中性炭黑。** 不用棕色、不用米色；surface 靠亮度抬升。
7. **对比度先过 4.5:1，再谈风格。** 小字/辅助文字按侧栏实际背景算，不按白色算。
8. **用语义 token，不用颜色名。** `--accent` / `--warning`，不要 `--gold` / `--blue`；否则下次换色还会把语义绑死。

## 6. 推荐

- **默认推荐 A**：它最接近 GitHub/Ant/Vercel 的成熟组合，风险最低，也最彻底地去掉土黄和淡蓝铺底。
- 如果你仍想要“纸感”，选 **B**；它不是把米黄调浅，而是换成低彩度暖灰，并把金色全部撤掉。
- 如果你想要更强的产品识别、且主要用暗色，选 **C**。
- **D 只作为无蓝实验**；它会把主色和危险色放得很近，需要额外的语义区分，不建议作为默认。

## 7. 诚实清单

- Linear、Notion、Craft、Bear、Raycast 的 hex 来自公开设计分析/界面观察，不是官方 token 文档；只作为方向参考，不作为规范值。
- 只计算了 WCAG 2.1 对比度，没有计算 APCA；APCA 更适合暗色和字重差异，但当前工具链没有接入。
- demo 只覆盖笔记页 + 侧栏 + 事实右栏，不是全部 16 个页面；没有做真实用户测试、色彩盲模拟、真实屏幕校色。
- 本文的 demo 是独立 HTML；应用内四套主题与设置页已另行落地，见 [`THEMES.md`](THEMES.md)。
