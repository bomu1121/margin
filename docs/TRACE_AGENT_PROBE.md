# 溯源 Agent 实验版（2026-11-21）

> **2026-11-21 起产品方向已改为“出处系统”：只把笔记原句关联到书名/原文，不再做事实判定。** 新框架见 [`CITATIONS.md`](CITATIONS.md)。本文保留为 agent 实验与对照记录，不是当前产品入口。

> **状态：实验，不是产品入口。** 只有 `production_trace_agent_probe` 命令和 `tools/probe-trace-agent.mjs`，没有任务类型、没有 UI、没有模板。它和 AI 成稿（`note_engine.rs`）不共享提示词、工具、上下文和输出契约；只共享事实库、provider 和 job/usage 这类基础设施。
>
> 目标：先验证一个判断——**让模型自己决定查哪条主张、用什么 query、读哪个来源、什么时候停，是否比固定流水线更接近“可信的溯源”**。

## 1. 一句话结论

**主语绑定是分水岭。** 第一版 agent 会把「这个项目支持四平台」改写成「这类项目支持四平台」，然后拿别的项目当证据，把 4 条无法归因的主张标成“可印证”。加上“保留原句主语 + 报可印证前必须抓正文 + verdict/relation 必须一致”后，同一篇笔记的 7 条具体主张全部被正确判为“无法归因”，没有再用别的项目顶替。

## 2. 它怎么跑

```bash
# 需要 app 在 CDP 9222 运行；会花真实模型/搜索调用
node --no-warnings tools/probe-trace-agent.mjs "<笔记标题片段>" "<输出目录>"
```

输出：`report.json`（完整轨迹）、`report.md`（人读版）、`facts.json`（写回笔记的事实）。

Agent 的工具：

| 工具 | 作用 | 约束 |
| --- | --- | --- |
| `find_facts` | 查事实库，命中就复用 `fact_id` | 只给候选，不自动合并 |
| `search_web` | 一个 query 一次搜索 | 总预算 10 次 |
| `fetch_source` | 抓一个来源正文 | 总预算 6 次；45s 超时 |
| `report_claim` | 提交主张 + 判定 + URL + 逐字引文 | URL 必须是本轮见过的；quote 必须是来源连续原文；报“外部可印证/存在争议”前必须 fetch 过该 URL |
| `finish` | 结束并写 summary | 必须调用 |

程序侧硬约束（不交给模型）：

- `source_url` 必须在本次 `search_web` / `fetch_source` 的 URL 集合里；
- `quote` 必须是该 URL 摘要/正文的连续子串（空白归一化后）；
- 外部可印证 → `relation=supports`；存在争议 → `relation=contradicts`；
- 每条主张按笔记原句提交，最多 8 条、14 回合；
- 只写 facts/evidence/mentions，不写 note.md。

## 3. 三次真实运行

| # | 笔记 | 结论 | 主张 | 搜索/抓取 | 耗时 | 成本 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 把主机游戏原生搬到 PC 和手机的开源工具 | 4 verified / 4 unsupported，但 verified 用的是**别的项目** | 8 | 8 / 2 | 63.0s | ¥0.0669 |
| 2 | 胡塞一发导弹打中沙特 PIF 总部 | 3 verified / 3 disputed / 1 candidate / 1 unsupported | 8 | 7 / 6 | 114.6s | ¥0.0893 |
| 3 | 同 1（加主语规则后） | 7/7 unsupported，明确写「主语无法定位」 | 7 | 3 / 0 | 20.2s | ¥0.0236 |

### 运行 2 真正查出来的东西

- **日期错了**：笔记写「10月19日」，抓到的报道是 **2026-11-19**；判 disputed。
- **“击中”不准确**：联军发言人说导弹被拦截、碎片造成损坏；判 disputed。
- **“140 多家企业/75 家区域总部”不是楼内**：来源说的是整个 KAFD 金融区；判 disputed。
- **可印证的**：PIF 大楼 385 米；THE LINE 2025-09-16 暂停施工；外立面/窗户受损。
- **未找到**：“7 到 8 个楼层”的具体层数。
- **单位问题**：笔记写「国防开支 6000 亿」，来源是「约 830 亿美元、全球第八」；agent 标了“仅非权威来源”，没有硬判。
- 受 8 条预算限制，2700 名美军、穆哈港 9 天、1 万无人机 vs 2000 万拦截弹等未核查；summary 明确列出了未核查项。

运行 2 的轨迹里有一条 `verdict=存在争议` 但最终落成 `candidate`：agent 没填 `relation=contradicts`，旧的状态映射只认证据关系。已加“verdict/relation 必须一致”的规则；这一条未复跑验证。

运行 3 证明了主语规则的收益：agent 先在 summary 里写「正文与 frontmatter 都没有项目名/仓库/来源链接」，然后把 7 条具体主张全部标为 unsupported，并明确说检索到的 sf2recomp、ZeldaWWHDRecomp、AnyPS5 都是别的项目，不能挪用。

## 4. 这次暴露的四个真问题

1. **主语绑定**：没有主语，具体数字/平台/功能就不能用“同类项目”来印证；必须保留原句主语，或明确写“无法归因”。
2. **摘要不等于证据**：仅凭搜索摘要报“可印证”会产生假阳性；这次加了“先 fetch 正文”的门槛，运行 2 抓了 6 页，才拿到日期和“拦截/碎片”这种矛盾。
3. **verdict 与 relation 必须一致**：旧 `status_for_verification` 会被关系字段带偏；agent 必须指出“哪句支持/哪句矛盾”，不能只给一个标签。
4. **事实身份与清理**：换一种说法就新建一条事实；运行 1 的 4 条“类别性 verified”仍在事实库里，运行 3 没有覆盖它们。生产版需要一次“本次任务的主张清单 + 事实归并/清理”，否则库里会留互相矛盾的旧结论。

## 5. 其他发现

- **GBK 页面之前是乱码**：运行 2 抓 `military.cnr.cn` 得到 mojibake，导致「830 亿美元」的引文无法校验。已在 `web_fetch.rs` 加 GBK/GB2312 解码（header + meta charset），并加单测；这次运行仍是旧解码，复跑才能验证。
- **预算决定覆盖**：8 条主张封顶时，agent 会优先处理开头的主张；一篇 4.4k 字的笔记有十几条可核查主张。生产版需要先做“主张清单 + 优先级”，再分配搜索/抓取预算。
- **成本**：单篇 20–115 秒、¥0.02–0.09；比固定流水线贵，但换来的是“哪条没查、为什么没查”的轨迹。

## 6. 已知限制

- 只有 probe，没有 UI/任务类型；不是 `note-trace` 的替代。
- 事实写进了真实笔记（两篇），没有删除命令；实验事实需要人工整理或后续加清理。
- 运行 2 的第一条主张状态未按新 relation 规则复跑；运行 3 没有覆盖运行 1 的旧事实。
- 历史主张（ctext/史料）没有接进 agent；当前只走网页。
- 只测了中文网页；英文/PDF/需要登录的来源未覆盖。
- 未做提示注入/恶意页面的对抗测试。

## 7. 下一步（按价值排序）

1. **主张清单 + 预算分配**：先列出全部原子主张，按“数字/日期/机构”排序，再逐条查；避免只查前 8 条。
2. **事实归并/清理**：把本次任务的 claims 与旧事实对齐；不能复用的旧事实要从这篇笔记的 mention 里摘掉。
3. **GBK 复跑**：用修好的 `web_fetch` 重跑运行 2，确认「830 亿美元」能被引文校验。
4. **历史来源**：把 `history_search`/`history_ingest` 作为独立工具接进来，先只返回候选，不自动写 citation。
5. **UI**：等行为稳定后再做成独立任务类型；不要塞进 AI 成稿的 job。

### 这张对照图真正说明的四件事

1. **复合主张两边都没拆**：01–03 是一条句子塞了 2–4 个断言；旧流水线拿一句细节差异判“争议”，hybrid 拿一份官方文件判“可印证”，都没有覆盖整句。先拆原子主张是两边共同的前提。
2. **单循环把证据串位了**：07（空管）拿到的是 08（“这就是生活”）的引文，08 拿到的是 07 的空管报道。`report_claim` 只校验“引文存在于来源”，查不出“引文属于哪条主张”。这就是为什么“推荐的组合”必须是**每条主张一个独立 agent**，而不是一个 loop 塞 10 条。
3. **旧流水线把细节差异当争议**：01/02/03/10 的旧 verdict 是 `contradicts`，引文多是“补了限定/换了数字”，不是真冲突；`FACT_AUDIT.md` 已经记录过同类误判。
4. **hybrid 更保守，但选源不稳**：04/05/09/10 判“弱源”，其中 05/09 有更直接的旧来源；它还没有“来源相关性 + 权威性”的评分。
