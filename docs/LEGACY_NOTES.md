## 为什么暂时不重跑

用户要先观察 AI 成稿 agent 一段时间；现在批量重跑会：

- 在链路还不稳定时产生大量失败任务和模型成本；
- 覆盖或打乱旧笔记里已经人工核对过的正文/出处；
- 让“哪篇已经重跑过”变得不可追踪。

**在用户明确说“开发完善了，可以重跑”之前，不要批量重跑、不要取消隐藏所有笔记。**

## 用户确认后怎么逐个重跑

1. 先记录旧笔记 id、相对路径、原始来源（front matter 的 `原始链接` / `来源`）。
2. 只对当前这一篇执行 `unhide`，不要一次放开多篇。
3. 用 AI 成稿链路按原始来源重新生成；新笔记成功后再对照旧笔记的正文与出处。
4. 对照通过后再决定旧笔记保留、归档还是删除；**不要在没有对照的情况下删旧笔记**。
5. 每篇单独记录：旧 id、新 job id、模型成本、出处数量、人工对照结论。

## 工具

```bash
# 查看隐藏数量和 id
node tools/hide-legacy-notes.mjs <vault> list

# 隐藏全部（已执行过；重复执行是幂等的）
node tools/hide-legacy-notes.mjs <vault> hide-all

# 只放开一篇（id 或相对路径）
node tools/hide-legacy-notes.mjs <vault> unhide yn-xxxxxxxx

# 放开全部（仅在用户明确确认后）
node tools/hide-legacy-notes.mjs <vault> unhide-all
```

改完 front matter 后重启应用，或调用 `reindex`，让索引器重新扫描。

当前开发库路径：`src-tauri/target/debug/sample-vault`。安装版如果指向别的 vault，先确认 `get_vault` 再执行；不要对不确定的目录批量操作。
