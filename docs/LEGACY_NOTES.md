> 2026-11-27 起，旧笔记不再用 `隐藏: true` 跟同步对抗。它们已移出 vault，私有备份 + 待更新清单在 app data；新会话不要把它们重新塞回笔记库，也不要重新加隐藏标记。

- **114 篇旧笔记已归档**：99 篇原本带 `隐藏: true`，加上 15 篇被同步复位成可见的根目录旧稿（历史 / 时事 / 科技 / 社会）。
- 备份位置：`%APPDATA%\com.yebian.notes\legacy-archive\2026-11-27\mirror\`，保持原相对路径；同目录有 `待更新清单.md`、`待更新清单.json`、`SHA256SUMS`。
- vault 里现在 **0 篇隐藏 / 39 篇可见**：22 篇 `更新待审/` + 17 篇 `待整理/`；索引 `notes=39`。
- 114 篇文件删除已由 sync 推给服务器；其他设备下次 pull 会同步删除。如果家里设备又推回旧稿，**不要再隐藏**：把它并进上述 `mirror/` 目录并在 `待更新清单` 里追加一行。
- 归档清单是**本机私有**的，不提交 Git、不参与同步；不要把它复制进 `sample-vault/`。

## 为什么暂时不重跑

用户要先观察 AI 成稿 agent 一段时间；现在批量重跑会：

- 在链路还不稳定时产生大量失败任务和模型成本；
- 覆盖或打乱新队列里已经人工核对过的正文/出处；
- 让“哪篇已经重跑过”变得不可追踪。

**在用户明确说“开发完善了，可以重跑”之前，不要批量重跑。**

## 用户确认后怎么逐个重跑

1. 从 `待更新清单.md` 选一篇，记录标题、原路径、原始链接、旧 id。
2. 用 AI 成稿链路按原始链接重新生成，产物进 `待整理/`，不要直接覆盖 `更新待审/` 里的新版。
3. 新旧对照：正文结构、事实、出处数量、人工核对结论。
4. 对照通过后再决定旧稿留在私有归档、删除，还是替换队列里的版本。
5. 每篇单独记录：旧 id、新 job id、模型成本、出处数量、对照结论。

## 工具

旧的 `tools/hide-legacy-notes.mjs` 只保留作应急（例如临时查看隐藏标记），**不要再用 `hide-all`**。归档/恢复直接操作 app data 的 `legacy-archive`：

```bash
# 找到当前私有归档
ls "$APPDATA/com.yebian.notes/legacy-archive"

# 查看清单
sed -n '1,40p' "$APPDATA/com.yebian.notes/legacy-archive/2026-11-27/待更新清单.md"

# 恢复一篇到 vault（先确认目标路径不存在）
cp "$APPDATA/com.yebian.notes/legacy-archive/2026-11-27/mirror/历史/xxx.md" \
   "sample-vault/历史/xxx.md"
```

恢复或移动文件后，调用应用里的 `reindex`（或重启），不要手动改索引库。

当前开发库路径：`D:\Develop\yebian\sample-vault`。安装版如果指向别的 vault，先确认 `get_vault` 再操作；不要对不确定的目录批量删除。
