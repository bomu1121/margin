# 标签体系（2026-11-23）

## 目标

标签只服务两件事：**检索分组**和**图谱关系**。不是知识图谱工程，也不按 agent 模板固定发。

规则：**先判断内容类型，再只打适用的 2–4 个标签；没有依据就不打。**

## 数据形状

- `tags`：只允许 `领域/`（1 个）和 `主题/`（1–2 个）。
- `人物`：只对 历史、时事、访谈 抽 0–3 个；技术/教程/科普/观点为 0。
- `时期`：只对 历史、时事 抽 0–1 个；历史写朝代/时期，时事写 `YYYY-MM` 或日期。
- 引用史料不进标签；继续走 `note_citations`（书名/卷次/页/原文/URL）。
- 不再产生 `类型/`、`来源/`、`其他/` 标签；自由标签不再从制作台输入。

## 内容类型

tagger 只把它当内部分支，不给用户看：

历史 / 技术 / 时事 / 访谈 / 教程 / 科普 / 观点 / 其他。

## 例子

历史《九个字里的官渡》：

```yaml
tags:
  - 领域/历史
  - 主题/官渡之战
人物:
  - 曹操
  - 袁绍
时期:
  - 东汉末
```

技术《大厂都在开发自己的 IDE》：

```yaml
tags:
  - 领域/技术
  - 主题/AI 编程
  - 主题/IDE
人物: []
时期: []
```

时事：

```yaml
tags:
  - 领域/时事
  - 主题/中期选举
人物:
  - 特朗普
时期:
  - 2026-11
```

## 链路

1. 笔记正文生成后，独立 `tag_note` 调一次模型：先判内容类型，再输出 `{genre,tags,people,periods}`。
2. `parse_tagging` 做硬约束：只留 `领域/`、`主题/`；技术/教程/科普/观点清空人物/时期；历史/时事保留；标签/人物/时期有上限。
3. 标签写进 `options.tags`，人物/时期写进 `entities`，由 outbox 写成 front matter。
4. 索引 `parse_file_at` 读 tags/people/periods；`领域/` 派生 domain。
5. 标签台只保留 5 组：领域、主题、UP 主、人物、时期。图谱的旧 evidence 组改名为「事实证据」，不再和笔记来源混用。

## 制作台精简

- 移除「标签」手填输入。
- 移除「抽取属性」人物/事件/时期/公司/概念勾选。
- 移除设置里的「标签与属性」页。
- 新建任务摘要只显示「自动：按内容类型打 2–4 个领域/主题标签」。
- 订阅任务不再从设置里取默认抽取字段。

## 验证

- 技术测试稿（IDE）：`领域/技术`、`主题/AI 编程`、`主题/IDE`；人物/时期为空。
- 历史测试稿（刘备/刘邦）：`领域/历史`、`主题/楚汉相争`、`主题/汉末三国`；人物 刘备/刘邦/项羽；时期 楚汉之际。
- 标签台只显示领域/主题/UP 主/人物/时期，类型/来源/其他不出现。
- `cargo test --lib` **242 passed / 7 ignored**；`npm run build` 通过。
- 安装包 `9,080,930 B` / 主程序 `23,279,616 B`（安装后 SHA256 `C56C3D12…`；release `0F26A4D0…`，3 字节 `UNK`/`NSS`）。

## 限制

- 旧笔记不重新打标；当前 18 篇实验/对照笔记没有 tags，只有 2 篇打标测试稿带新标签。
- 没有手动改标签的 UI；需要时先重新生成或等后续加轻量编辑。
- 技术/时事等分类由模型判断，可能误判；误判时人物/时期会被强制清空或保留，需要观察。
- 事件没有独立 facet，归到 `主题/`；如果以后确实需要事件图谱，再单独加一层，不现在扩。
