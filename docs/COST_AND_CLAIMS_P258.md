# 制作成本账本 + claims 基线（2026-11-27，P258）

> 目标：先让“钱花在哪”和“出处为什么不够”可测，不继续接 MCP。

## 1. 制作成本账本

### 改了什么

`production_get` 返回的 `JobDetail` 新增 `cost`：

- `aiCost`：AI 调用费用（按任务创建时的模型价）
- `asrCost`：音频秒数 / 60 × 任务创建时的 ASR 单价
- `totalCost`：两者合计
- `asrPriced` / `aiPriced` / `fullyPriced`：分开标识哪一段没价

任务详情「用量」新增三格：AI 费用、ASR 费用、已计价合计。ASR 单价为 0 时明确显示 **「ASR 未计价」**，不再把未知转写成本混进总额。

### 单价来源与实测

小米 MiMo 官方定价页（2026-11-18 更新）给出 `mimo-v2.5-asr`：国内 **¥0.5/小时**，即 **¥0.008333/分钟**，按输入音频秒数折算小时计费；海外 $0.074/小时。没有 ASR 免费额度（TTS 的限时免费不适用于 ASR）。

设置页已写入 **¥0.0083333333/分钟**。历史任务创建时单价为 0，因此任务详情会按当前设置补算，并标「按当前设置补算」；之后创建的任务按任务创建时配置计价。

最近 10 条 B 站任务：

- 音频 **233–1,418 秒**
- AI 费用 **¥0.0762–¥0.1895**
- ASR 费用 **¥0.0324–¥0.1969**
- 合计 **¥0.1085–¥0.3865**
- 除一条中断任务只有 ASR 外，其余任务的 ASR 占总费用 **25.0%–52.1%**

示例（8:08 的视频）：AI ¥0.0976 + ASR ¥0.0679 = **¥0.1655**。

**旧估算金额确实只含 AI**；补上真实单价后，转写成本不是可有可无的小项，而是单篇成本的 **四分之一到一半**。

### 官方日账

“语音识别”设置新增只读「官方用量（MiMo 日账）」：后端用已保存的 ASR Key 调：

```http
GET https://api.xiaomimimo.com/v1/platform/usage/daily?start_date=...&end_date=...
```

返回 `consumed_amount`、`request_count`、`audio_transcription_seconds`，按 UTC 日期和 masked Key 聚合。

实测近 7 天（2026-11-21 → 2026-11-27）：

- 总消耗 **¥6.0386**
- 请求 **763**
- 音频 **43,478 秒 / 724.6 分钟**
- 两个 Key：¥2.50 / 316 次 / 300.3 分钟，¥3.54 / 447 次 / 424.4 分钟

注意：

- 官方日账包含账号下所有 Key，可能混有其他设备/应用；
- `consumed_amount` 是折后金额，尚未扣赠送金；实际应付要再看日账单；
- 没有 request id，无法和单篇任务逐条对账，只能按日期/Key 核总账。

### 边界

- ASR 事件没有单独的逐次 usage 记录，只能按音频秒数 × 单价计算；
- 历史任务当时单价是 0，现在按当前 MiMo 单价补算，并在 UI 标「按当前设置补算」；不是历史账单原始值；
- 如果任务使用别的 ASR 引擎，不会套用 MiMo 单价；
- 官方日账与本地任务账本粒度不同，不能直接相除；
- 官方价格和实际折扣/赠送额度可能不同，日账 API 也不是最终账单。

## 2. claims 基线

工具：`tools/audit-ai-claims.mjs`（只读，CDP）
数据：`docs/ai-claims-audit.json`

当前 44 篇带 claims 的笔记：

| 指标 | 数值 |
| --- | ---: |
| claims 总数 | **205** |
| 可引用（史载/转述且 work 非空） | **54** |
| 可引用率 | **26.3%** |
| 有原文 claims | 17 |
| 有可用 claims 的笔记 | 13 |
| 全部待查的笔记 | 25 |
| note_citations 总数 | 39 |

典型分布：

- 《【老吏视角】读原始材料，看真实历史》8/8 可引用；
- 《在李世民的贞观之治…》8/8；
- 大量时事/科技视频 0/6–0/8；
- 《太香甜了，美军在爱荷华州…》0/8，但 2 条 candidate。

### 结论

- claims 低可引用率不是单一模型 bug：很多素材本身没有书名/原文；
- 下一步应优先接**本地史料候选**和**逐字 quote 校验**，而不是再接字幕/浏览器；
- 先把 20 条历史视频的可引用率从 26.3% 提到 **≥50%**，再谈其他自动化。
