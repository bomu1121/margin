# 出处系统（note_citations）

> **状态：三篇 15/15 条出处有原文（2026-11-22）。** 这是对“事实/溯源系统”的降级替代：产品概念只剩两个——**笔记里的一句话**，和**它出自哪里**。
>
> 旧事实系统、史料目录、候选队列的数据**不删**；事实页保留为档案，笔记右栏不再展示事实/判定。

## 1. 为什么重做

用户的需求不是“判真假”，而是：

> 一篇历史文章里提到的内容，出自哪个历史记载，能顺着链接读到原文。

旧系统按“事实核查”建模，长出了事实、状态、证据、核验历史、合并、拆分、冲突、复核、候选队列、来源等级。对学习历史的人来说，这些展示过量和分类繁琐；真正的产品动作只有“这句话出自哪本书”。

## 2. 数据模型

新表 `note_citations`：

| 字段 | 含义 |
| --- | --- |
| `note_id` / `note_quote` | 笔记和逐字原句 |
| `work_title` / `author` / `volume` / `page` / `locator` | 书名、作者、卷/页/位置 |
| `original_text` | 史料原文（逐字） |
| `url` / `snippet` / `provider` | 候选链接、摘要、来源 |
| `status` | `found`（有原文）/ `candidate`（待补原文） |
| `passage_id` / `source_id` | 已入库原文段落/来源；候选为空 |

复用现有 `sources` / `source_passages`（史料目录）和 `history_search_candidates`（候选队列），不新建一套史料库。**不写 facts、不写 note.md。**

## 3. Agent 的角色

`cite_agent.rs` 是“史料管理员”，只做找/读/贴：

- `find_candidates`：从已有候选里找书名/标题/摘要；
- `list_sources`：从已入库史料目录找书；
- `read_source`：读一本书的原文段落；
- `attach_citation`：绑定“笔记原句 ↔ 已入库原文”；
- `attach_candidate`：绑定“笔记原句 ↔ 候选（书名+链接，待补原文）”；
- `finish`：结束。

另外，AI 成稿会输出 `yebian-claims` HTML 注释块；`cite_agent` 优先走确定性 claims 路径：只处理 `史载/转述`，跳过 `判断/待查`，quote 必须逐字在正文，有 `original` 直接 found，否则 candidate。**这条路径不调用模型、不需要 API Key**；没有 claims 的旧笔记继续走上面的模型/tool 流程。

硬规则：

- `note_quote` 必须逐字出现在笔记正文里；
- 不判真假、不写事实、不写白话、不改笔记；
- 不编造书名/卷页/原文；找不到就留候选或空；
- 最多 6 条出处、12 回合；**达到 6 条立即结束**，不再空转到 12 回合。

## 4. 笔记右栏

```text
出处 6
6 条出处 · 0 条待补原文                加出处  重新找出处

“在彭城的薛安都看到刘彧摆出这个架势，自然怕了…”
《魏書》                 改原文  打开来源 ↗  删除
｜初，彧遣其鎮軍張永、領軍沈攸之以大眾迎其徐州刺史薛安都。
  安都聞永將發，乃遣信請降。顯祖詔博陵公尉元、城陽公孔伯恭率騎二萬救之。

“我正要趁此机会北讨，你觉得如何？”
《資治通鑑》             改原文  打开来源 ↗  删除
｜上不從，謂征北司馬行南徐州事蕭道成曰：「吾今因此北討，卿意以為何如？」
```

- 有原文：卡片直接显示原文；没有原文：`补原文` + `打开来源`。
- 有原文后可 `改原文`；任何一条都可 `删除`（弹确认），计数即时更新。
- 卡片带 `已找到` / `待补原文` 小状态标签；提示文案根据“是否有可打开链接”变化，不会承诺不存在的 `打开来源`。
- 不再显示 verdict、来源等级、检索/抓取数、事实合并/拆分。
- 旧“事实”tab 已从笔记右栏移除；顶部导航的“事实”页保留为档案，不参与新流程。

## 6. 已知限制

- 三篇共 15 条出处，**15 条都有原文**；原文是逐条核对/粘贴的，没有自动对齐。
- 正文未改；北魏“十之八九”、曹操“头骨”与史源的差异保留在出处卡片，避免以后正文和出处两边都要维护。
- agent 的自动收尾是代码与单测层面的修复；华佗那次 `max_rounds` 是修复前数据，尚未用真实模型复跑确认；陈寿这篇是 `success` 自然结束。
- 补原文只保存文本，不自动切 passage、不做逐字校验；后续可接现有 `history_ingest` 的对齐逻辑。
- 关羽传链接指向 ctext《三国志》书目页，不是精确篇章；原文已直接存在卡片里，链接只作入口。
- 北魏“十五万”存在版本异文（部分《資治通鑑》版本作“五万”）；当前卡片按《通鑑紀事本末》的“十五萬”填，并在正文里保留原文。
- 陈寿笔记“评价最好的几个人之一”是作者判断；《三国志·评曰》只支持“识治之良才，管、萧之亚匹”的高评价，不是字面排名。
- AI 成稿历史笔记只测了 1 次（素材还是旧北魏笔记正文）：6 条候选、0 直达原文、至少 3 条错归；当前不能当作“AI 成稿可直接出处化”。要常用，需要让 AI 成稿输出“史源/原文”块，或让出处 agent 只处理【史载】句并要求原文。
- P170 已落 claims 路径：AI 成稿自愿输出 claims 块；完整北魏长稿用第一版 prompt 时模型卡在回合、被取消，缩短 prompt 后小素材成功；长稿未复跑。`待查` 不落出处；installer 尚未包含 P170 代码。
- 旧事实/史料数据保留，没有迁移或删除；旧事实页已从主导航移除，只保留设置 → 关于的“旧事实档案”入口。
- 只测了三篇旧链路历史笔记 + 1 篇 AI 成稿对照；没有批量回归；安装包已重打。
