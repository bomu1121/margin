# 运行页设计：把「流程 tab」升级成可观测的运行控制台

> 2026-11-18 · 目标：任意制作时刻都能看到「现在跑到哪、为什么慢、这一步做了什么」，点节点能看实时日志、产物和指标。  
> 参考：Airflow Graph + Task Instance、Temporal History、Inngest Run Trace、n8n Execution Timeline、Dify Workflow Canvas。

## 1. 参考产品里真正有用的东西

| 产品 | 可借的点 | 不借的点 |
| --- | --- | --- |
| Airflow Graph | 左图右检查器；节点状态 + 任务组；选中节点蓝框；日志级别/来源筛选、搜索；图上有缩放/布局/过滤工具条 | 任务图过密；节点文字小 |
| Temporal | 运行头（Workflow ID、开始、耗时）；History 的 Compact / JSON 多视图；Stack Trace；从运行页直接 Cancel/Signal | 事件流偏工程化，不适合非后端用户 |
| Inngest | 运行头 + Trace 瀑布图；每个 step 可展开看重试和耗时；右侧 Input/Output JSON；Rerun from step | 全英文、信息密度高 |
| n8n Execution | 图上节点状态 + 单独 Execution Timeline；失败节点红色 + 错误卡；移动端有简化视图 | 编辑器与运行视图混在一起 |
| Dify Workflow | 大画布 + 节点卡端口；右侧预览/日志；深色画布、点阵背景 | 画布偏编辑，不是运行监控 |

共同结论：**一个运行页 = 运行头 + 图/时间线 + 检查器**，三者都要围绕「当前节点」联动；图负责空间关系，时间线负责耗时，检查器负责证据。

## 2. 现在的流程 tab 差在哪

- 它是任务弹窗里的一个 tab，右侧还被 320px 任务信息栏占着，主区只剩 ~640px；图被压成 4 列蛇形，第二行反向，读序困难。
- 节点卡 160×72，标签 12.5px、meta 10.5px；低于可读下限，信息却仍然只有「耗时/tokens」。
- 没有缩放/平移/适配；节点一多就换行，没有画布感。
- 检查器是画布下方的一大块，日志 11px，首行被自动滚动裁掉；没有概览/输入输出/产物/指标分区，没有搜索、级别筛选、跟随开关。
- 没有时间线/瀑布图；看不出「时间花在哪个节点」。
- agent 的 5 个回合只在一个节点里，图上没有回路/子步骤；`#5 look`、`#7 read_file` 这类过程只能翻日志。
- 1.5s 轮询同时拉全量 job + 全量日志 + 全量 run graph；运行中会重复渲染整页。
- 假成功：max rounds 被当成 done，页面显示「完成」，实际没 patch（P126 已修）。

## 3. 新页面：`/studio/run/:id`

### 3.1 布局

```
┌ 顶栏：← 任务 · 标题 · 状态 · run id · 开始/耗时 · tokens/¥ · [实时|暂停] [刷新] [取消/重跑] ┐
├───────────────────────────────────────────────┬──────────────────────────────┤
│ 画布工具条：阶段图例 · [适配] [−] [100%] [+]   │ 检查器（380px，可收起）       │
│                                               │ 节点名 · 状态 · 耗时 · 尝试   │
│   [生成]  来源 → 大纲 → 分章 → 组装            │ ┌ 概览 ┬ 日志 ┬ 产物 ┬ 指标 ┐ │
│                         ↓                     │ │ 状态/时间/用量/输入输出   │ │
│   [质检]            智能体修订 ×5             │ │ 日志：级别/搜索/跟随      │ │
│                         ↓                     │ │ 产物：预览/打开           │ │
│   [入库]              入库                    │ │ 指标：inspect 六项         │ │
│                                               │ └──────────────────────────┘ │
├───────────────────────────────────────────────┴──────────────────────────────┤
│ 时间线（可折叠）：0s ── 大纲 18s ── 分章 18s ── 组装 8s ── 智能体 25s ── 63s │
└──────────────────────────────────────────────────────────────────────────────┘
```

- 1440 宽：画布 ~1000 + 检查器 380。
- 1040 宽：检查器改为覆盖式抽屉（默认收起），画布占满；点节点/时间线打开抽屉。
- 画布支持滚轮缩放、拖拽平移、双击适配；缩放范围 0.5–1.6，100% 按钮复位。
- 阶段用浅色背景带 + 左上角 label：生成 / 质检 / 入库。不是每个节点一个颜色。
- 节点卡：156×80，标签 13px/600，状态 11px，耗时/tokens 11px mono；运行中显示进度环/脉冲；选中蓝框；失败红框；跳过虚线。
- agent 节点 180×96：右上「×5 回合」，第二行显示当前工具（`inspect` / `patch_figure` / `review`），选中后检查器默认打开「回合」。
- 边：正交折线 + 箭头；运行中的边流动虚线 + 光点；失败边红色虚线；跳过边点线。agent 自回路用一条小弧 + `×N` 表示「模型→工具→观察」的循环，不把 5 个回合硬塞进主图。

### 3.2 运行头

- 左：返回、标题、模板 badge、状态 pill、run id（可复制）。
- 右：开始时间、耗时（运行中实时走）、tokens、估算金额、尝试次数；操作：暂停/继续实时、刷新、取消、重跑、打开笔记。
- 状态：运行中（蓝）、成功（绿）、失败（红）、已取消（灰）、等待（金）；必须「点 + 文字」，不能只靠颜色。

### 3.3 检查器

四个 tab：

1. **概览**：状态、开始/结束、耗时、tokens、成本、attempt、summary/error；输入（节点 key、step index、参数）和输出（summary、产物数）；agent 额外显示目标、模型、工具白名单、回合数。
2. **日志**：时间、级别、消息；级别筛选（全部/信息/警告/错误）；搜索；自动跟随开关（用户上滚自动暂停）；长消息默认折叠 4 行，点「展开」；agent 日志按 `#n` 分组为回合标题，工具名做成 chip，observation 折叠。
3. **产物**：名称、类型、大小、sha256 前 8 位；文本/JSON 内联预览，PDF/PNG/HTML 提供「打开」。
4. **指标**：解析最近一次 `inspect` 的六项（溢出/越界/小字/SVG 越界/空框/标签重叠/文字溢出），每项 0 为绿、非 0 为红；显示对应的图号/标题/文字；没有 inspect 时显示「该节点没有版面指标」。

检查器底部固定一条「跟随当前节点」：图/时间线选中哪个节点，检查器就换哪个；不自动抢滚动。

### 3.4 时间线

- 横轴：运行开始 → 现在/结束；每个节点一段，宽度按耗时；颜色按状态；点击段选中节点。
- agent 段下方展开 5 个回合的子段（从 run JSON 的 turn startedAt/endedAt 来）；悬停显示 `#3 patch_figure · 2.1s`。
- 顶部有「总耗时 63s」「生成 38s」「智能体 25s」三个直接标注；不另做卡片。
- 运行中实时增长；暂停实时后冻结。

### 3.5 实时

- 新命令 `production_run_snapshot(job_id, after_log_id)` 返回 `{ job, graph, logs, lastLogId }`；运行中 800ms 轮询，只取增量日志；暂停/页面隐藏时停止。
- `document.visibilityState === 'hidden'` 时暂停；回来补一次全量。
- 运行结束后停止轮询，显示最终状态；失败时自动选中错误节点并打开错误详情。
- agent 回合：worker 每回合写 `production_agent_log`（P126），日志里能实时看到；选中 agent 时优先用 `productionAgent.turns`（同页内存）做回合条，完成后回退到 `agent-run.json`。

### 3.6 视觉

- 沿用项目的纸感/墨色 token；画布加极浅点阵；不要做成通用深色 dashboard。
- 字号下限 11px；正文 12–13px；日志 12px mono；节点标签 13px。
- 状态色只用于状态点/边框/细条，不做大面积填充。
- 动效只表达「数据在流动」：运行边虚线 + 光点、运行节点脉冲、实时点呼吸；`prefers-reduced-motion` 全关。
- 空态：没有 run graph 时用 job.steps 画 queued 节点 + 骨架；失败态：错误节点红框 + 检查器错误卡。

## 4. 数据与接口

- `production_run_snapshot(job_id, after_log_id)`：job + run graph + 增量 logs + lastLogId。
- `production_logs_after(job_id, after_id, limit)`（store）：`SELECT ... WHERE job_id=? AND id>? ORDER BY id LIMIT ?`。
- agent 回合：`agent-run.json` 产物（已有）；live 用 `productionAgent`。
- 节点输入/输出：run node 的 summary/error + artifact meta；step 的 detail；v1 不新增 inputs_json。

## 5. 验收

- 1440 / 1040 两档：无横向溢出；节点标签/日志 ≥11px；检查器不遮住当前节点（覆盖式抽屉可关）。
- 运行中：图/时间线/检查器 1s 内更新；活动边有动效；暂停后数字冻结；恢复后补齐。
- 点节点：检查器切到该节点，日志/产物/指标正确；上滚后不被新日志抢滚动。
- 失败任务：错误节点自动选中，错误信息在概览和日志里都能看到。
- 真实运行截图：运行中、成功、失败各一张；浅色 + 暗色各一张。

## 6. 实现与验收（2026-11-18）

### 6.1 落地

- 路由：`/studio/run/:id`（`ProductionRunView.vue`），隐藏笔记/制作侧栏，整页运行控制台；任务详情「运行 ↗」直接进这个路由。
- 组件：`RunGraph.vue`（阶段化 DAG、缩放/平移/适配、选中节点避让抽屉）、`RunTimeline.vue`（waterfall，可展开 agent 回合）、`RunInspector.vue`（概览/日志/回合/产物/指标）。
- 数据：新命令 `production_run_snapshot(job_id, after_log_id)`，返回 job + run graph + 增量日志；运行中 800ms 轮询，页面隐藏/暂停时停；`logs_after` 只取新行。
- 实时：agent 每回合的 `production_agent_log` 已进任务日志；检查器「回合」用 live turns，结束后回退 `agent-run.json`。
- 冻结：暂停时页头、图、时间线、检查器的时钟都停；恢复后补齐。终端任务里残留的 `running` 节点按最后一条日志冻结（interrupted/cancelled），不再出现“运行 294 分钟”。
- 时序：runtime 的 `record` 改成记录工具实际开始时间；回合现在有 inspect 6s、look 4s、review 8s 这类真实耗时。

### 6.2 实测

- 任务 16,739 / 12,632 tokens（29,371），¥0.0721；图/时间线/检查器在运行中 1s 内更新，活动边有 `run-dash` + spark，节点有 `run-pulse`。
- 暂停测试（任务 H）：暂停时耗时停在 1m08s，4s 后仍是 1m08s；继续后跳到 1m40s；取消后任务、agent 节点都显示已取消。
- 中断任务：`04 章节大纲` 显示「已中断 42s」（最后日志 11:31:52），修复前会显示 294m。

### 6.3 边界

- 日志是 800ms 轮询 + 增量，不是 token 级流式；模型单次调用期间看不到中间 token。
- 回合耗时是工具执行时间（inspect/review 等），模型思考时间没有拆到回合；节点耗时包含模型时间。
- ≤1180px 时检查器是覆盖式抽屉；打开时图自动左移避让选中节点，但时间线右半会被遮住，关闭抽屉才能看到完整时间线。
- 终端任务的冻结时间取该 step 最后一条日志；没有日志时取 job.updatedAt，仍可能偏晚。
- 任务详情里旧的流程面板已不再可达（「运行 ↗」走新路由），旧面板代码还没删，属于清理项。
