# 把 Agent 拆成项目经理与工程师，只留一个对接人

## 结论

- 它是什么：把 Agent 从单次会话解绑的双层架构，router 只沟通派活，worker 各带上下文干活。
- 值得抄：trigger 走快慢两路过滤、thread 订阅绕过 router、状态与环境分别外置。
- 不搬：默认开着的主动性——主动干活要有预置规则，原型默认只观察不动手。

## 1. 它要解的问题

现在的 agent 以会话为单位：开一个会话布置任务，在里面想一步、做一步、看结果再想下一步，这个循环叫 ReAct loop，单任务上好用。但人同时开着修 bug、写文档、跑测试几个会话时，它们互相不知道对方在干什么，跨任务信息只能靠人记住再手动搬，人就成了"一群 AI 之间的传话筒"。DeepSeek 的说法是：单任务的上限取决于模型能力，多任务的上限取决于人的注意力——人通常只能同时跟进三到五个活跃会话。

接飞书、用 CLI 和 MCP 让它自己去群里接任务也不够：底层还是单会话，就会撞三件事——跑耗时命令时循环卡住；几个需求塞进一个会话，上下文越来越乱；Agent 在本地，一休眠就罢工。所以要让它和单次会话解绑，变成跨会话记上下文、同时推进多件事的连续工作者。

限定条件得留着：它没说单会话不好，措辞是单任务上"挺好用"；它治的是人开多个会话的混乱，不是模型能力不够；"主动不等于乱来"——没人要求的主动工作必须有提前写好的规则，默认只记录不动手；"全双工"口播说很多 AI 工具已经实现了。

## 2. 一条消息从进来到回你，经过谁

### 门口的门卫和秘书

**职责**：把环境里发生的事变成一条"要不要管"的判断，尽量不动用大模型。

**怎么做**：环境事件统一叫 trigger：群消息、PR 评论、构建失败。门卫只看来源——是不是监听的群、发消息人在不在白名单，普通代码秒判；放行的交给秘书，由大模型按提示词规则读内容。这是快慢路径（fast path / slow path）：多数流量在快路用便宜手段挡掉，少数才进慢路花大钱。

**失效时**：门卫判来源不判内容，新群、私聊里的真需求被无声丢掉且不报错；秘书规则写宽了当任务、写窄了漏需求。

**原文说法**："门口先有个门卫，后面再有个秘书"；"每条消息都让大模型判断一遍要不要管，又慢又烧钱。"

### router：项目经理

**职责**：常驻在线，消息先到它这里，它记全局、跟你沟通、派活，自己不干活。

**怎么做**：招一个项目经理再配几个工程师——二十件事全给一个人，信息不断但只能排队；每件都找新人能同时开工，却互相不同步、还要一人一嘴来汇报。router 不干活，轻量模型就够；决定交付质量的是 worker，配最强模型。它忙不过来就把新消息攒着一起派，于是消息越多、平均处理反而越快。

**失效时**：唯一入口就是单点，它挂掉全渠道停；批处理降平均成本不降尾部延迟，急事要陪一批闲聊等；派活压在轻量模型加提示词上，派错全盘皆输。

**原文说法**："上层的 router 层相当于项目经理，下层的 worker 层相当于工程师。"

### worker 与 thread 订阅

**职责**：在独立上下文里专心干完一件，干完向 router 汇报。

**怎么做**：每条消息都过 router 转手它会垮，于是借"工单分给小王，之后的消息直接抄送小王"。同一 PR、同一群话题、同一串邮件里的连续消息叫 thread，也就是工单；worker 订阅它，后续消息由程序直送、不再经过 router，省大量 token。worker 之间不直接沟通：两人改同一 PR 会同时收到该 PR 的动态，自己协调；活太复杂还能拉 sub agent，"相当于工程师自己带了实习生"。

**失效时**：thread 归属判错（话题中途换了、同一 PR 拆成两条线）就两人抢一件事或谁都没接，不报错不告警。

**原文说法**："同一串邮件里的连续消息叫做一个 thread，你可以理解为一个工单。"

### 链式召回与投机执行

**职责**：决定派下去的 worker 该看多少资料——给多了重点被淹没，给少了反复回头来问。

**怎么做**："浪费上下文窗口就是浪费模型的智能。"inline 内联，像同事转消息时顺手附上前后几句和工单号；spill 溢出，像几万字文档只给摘要加一句"完整内容见这里"。到系统里就是链式召回：消息、工单、worker 都编号，卡片只写摘要和关联编号，提旧事时顺编号往下翻。投机执行则是先算好再说：收到会议邀请就先去核对日程、备回复草稿，用不上就扔。

**失效时**：摘要写偏就一路翻偏，而每一跳都像有人确认过；spill 一趟没翻到位得多跑一轮，延迟堆长尾；投机落空是纯烧 token。

**原文说法**："就像同事给你转消息时，顺手附上前后几句聊天和相关的工单号。"

### 存算分离、Daemon 与看门狗

**职责**：让它一直在线，并且在它跑偏时有人拉一把。

**怎么做**：本地把计算、会话状态、执行环境绑在一台电脑上，休眠就全停。第一步拆计算和状态：计算进云端可替换的容器，状态进数据库，容器挂了换一个、记录不丢，像工作记录放进档案室，谁接班都能接着干。第二步拆计算和环境：代码、密钥、内网服务搬不上云，那就别搬——大脑留云端，电脑上只装很轻的 Daemon，不存记录、只按指令执行并回传，像远程专家指挥现场助手，这叫 BYOM。主系统外另配 Watchdog，按任务有没有进展而非在不在岗判异常——出问题常是模型在原地打转。

**失效时**：Daemon 只执行不存状态，机器离线时动作只能排队，排久了"有没有进展"自己失真；看门狗按进展判，缓慢但方向错的活被判正常，它失联也没人看；状态在库里、环境在机器上，对不上时云端不知对着哪份环境。

**原文说法**："既然环境搬不动，那就别搬了。"

## 3. 它放弃了什么

- 放弃"一任务一会话"，改 worker 独立上下文加编号召回：多任务不再互相污染，代价是信息必须显式走召回链，缓存 token 翻到接近四倍。
- 放弃"最了解全局的人亲自干活"，router 只配轻量模型：省下大模型成本，代价是它得靠批处理顶流量，急事等批次。
- 放弃"每条消息都过一遍模型"，门卫用白名单和代码硬判：省了钱和延迟，代价是白名单外的需求被安静丢掉、没指标能看出。
- 放弃"agent 只活在你这一台电脑上"，拆成云端容器加本地 Daemon：休眠不等于下班，代价是多一条网络边界，本地环境可能与云端对不上账。

## 4. 数字与口径

- 三到五个活跃会话：对"一个人同时能跟进多少"的观察，不是测量；它是"上限取决于人的注意力"的来源。
- 速度快了一倍：DeepSeek 自己做的对比实测，比较对象是"传统的单对话 Agent"；任务集、模型、并发度、计时起点没给，只能当方向。
- 读缓存 token 是单会话方案的两倍到将近四倍：同一对比的另一面，也是唯一被明说为代价的数字，它随并行任务数上涨，所以这条是代价在涨。
- 飞书单次回复不超过一百个词：给 router 定的渠道规矩，是产品约束不是测量值。

## 5. 落地时先做什么

- 先劈开 router 与 worker：触发条件 是单会话已塞进多个不相关任务、或长命令一跑循环就堵；最小改动 是把现有会话原样留作 worker，另加一层只做接线派活的轻量调度；成功判据 是长命令期间仍能接新消息、派活不丢消息。
- 先做两级过滤再谈主动：触发条件 是想让 agent 自己盯群和工单；最小改动 是先用来源与白名单硬过滤，只把放行的交给模型，主动行为默认只记录；成功判据 是"打算做的事"误报可接受、没有未确认的写操作。
- 先把状态挪出执行环境：触发条件 是"电脑休眠任务全停"或"容器重启丢上下文"；最小改动 是状态外置、执行端换成只按指令执行并回传的轻量程序；成功判据 是换容器后记录不丢、机器上线后积压任务自动补做。

## 6. 明确不做什么

- 不把 worker 的推理过程发到对外渠道：冗长思考全关在 worker 里、只有 router 说话，否则群消息会被刷爆。
- 不让 worker 之间直接对话协商：只靠共享同一 PR 的事件各自协调，否则并行度一上去就多出一张互相汇报的网。
- 不让没有预置规则的主动行为真动手：原型默认只记录打算做什么。

## 7. 还没答案的问题

- router 的批处理窗口该多大？什么条件下值得把一个 thread 立刻旁路给 worker 而不等下一批——这个阈值没给。
- 连续跑上几个月后，长期记忆放哪一层：router 的全局记忆、thread 卡片的编号链，还是外部检索？三处冲突以谁为准？
- 提示词注入的边界落在哪一环：worker 读的 PR 正文和工单描述本身就是不可信输入，工具权限要不要按 thread 收窄。

## 8. 术语 ↔ 它在系统里的位置

- **ReAct loop** → agent 在单会话里"想一步、做一步、看结果"的循环，正是被半双工卡住的那个东西。
- **router 层** → 常驻的项目经理与唯一入口，负责全局记忆、对外沟通、派活。
- **worker 层** → 工程师，带独立上下文干一件具体的事，配最强模型，可再拉 sub agent。
- **trigger** → 环境里发生的事（新消息、PR 评论、构建失败），所有流程的起点。
- **thread** → 同一 PR、群话题或邮件串里的连续消息，相当于工单，也是订阅与路由的键。
- **chain of recall** → 消息、工单、worker 全编号，卡片只写摘要与编号，需要时逐跳回溯。
- **Daemon / BYOM** → 本地只执行不回存的轻量程序；环境搬不上云就让云端指挥它。
- **Watchdog** → 主系统之外独立运行的值班会话，按"任务有没有进展"而非"进程在不在"判异常。

- 两个性能数字没有测试条件：任务集、模型、并发度、缓存口径、"快一倍"的计时起点都没给，不能当基准；三到五个会话与"二十件事"属于观察和类比。
