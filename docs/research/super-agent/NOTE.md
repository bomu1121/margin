# 先补「有进展」判定，再谈多层架构

## 一句话押注

承认：Super Agent 说对了单会话的两个硬伤——react loop 是半双工的，跨会话上下文全靠人搬。
反对：把 router/worker、存算分离、BYOM 三件一起搬进单机应用，多出来的状态没有消费者。
赌：真正能兑现的是「有进展」判定，一个 last_progress 时间戳加一次定时巡查，比整套分层更早见效。

## 机制表

| 机制 | 解决什么 | 成本 | 抄不抄 |
| --- | --- | --- | --- |
| 每个 step 记 last_progress_at，超阈值置 stalled | 进程没挂但原地打转看不见 | 低（<1天），加字段与扫描定时器 | 抄：已有 checkpoint 与 interrupted 状态 |
| 独立 watchdog 定时巡查，判「有进展」不判「活着」 | 模型跑偏无人介入 | 中（1-3天），巡查循环与判定规则 | 看情况：stalled 能自动重启后再上 |
| 工具调用异步化，结果作为新消息回投 | react loop 半双工，长命令卡住循环 | 中（1-3天），调度改成事件回投 | 看情况：单步常跑 >30 秒才做 |
| 卡片式召回：摘要 + 编号，全文 spill 到存储 | 历史记录淹没上下文窗口 | 中（1-3天），存档层加索引 | 抄：笔记条目本身已有 id |
| 事件入口两级过滤：代码判来源、模型判内容 | 每条事件都过大模型太贵 | 低（<1天），入口加白名单分支 | 看情况：接了非自己产生的事件源 |
| 主动动作默认 observe，只记录不动手 | 主动行为不可回滚 | 低（<1天），加 dry-run 开关 | 抄：任何主动逻辑上线前必过 |
| router 只派活用轻模型，worker 独占强模型 | 上下文与成本按角色分配 | 高（>3天），要拆出常驻路由层 | 不抄：单用户单队列，无工单可分流 |
| 计算 / 会话状态 / 执行环境三分（BYOM） | 机器一休眠全线停摆 | 高（>3天），要拆运行时与守护进程 | 不抄：本地单机没有可换容器 |

## 回到我的系统

- 给每个 step 加 last_progress_at，配一个后台 tick 把超阈值任务从 running 切到 stalled；判据 手动中断一个长命令后 30 秒内状态是 stalled，重启应用仍能从原 checkpoint 续跑。
- 把 stalled 与 retry 分成两个入口，stalled 走「保 checkpoint 重跑」路径，不动已有的失败重试；判据 一个死循环任务被 stalled 逻辑重跑一次，step 产出物不丢。
- 所有主动/自动动作先写一条 dry-run 记录再决定是否执行；判据 一次 30 分钟会话能导出「本会做但没做」的清单，条数与真实执行数相加等于触发总数。
- 不做 router/worker 两层：本地单用户没有并行工单可分流，多一层只多一份没人看的状态。
- 不做存算分离与 BYOM daemon：没有可替换的云端容器，拆完只是把同一个进程换个地方起。
- 不做 thread 订阅绕过 router：前置条件是先有 router，现在没有。

## 坑

- watchdog 只判进程存活等于没做：agent 出错时进程通常还活着，死循环和正常运行在进程表上完全一样，覆盖率接近 0。
- 阈值卡太紧会误杀长命令：一个正常跑 10 分钟的 step 和卡死 10 分钟的 step 在时间戳上无法区分，阈值必须按 step 类型分设，或让长命令自己定期上报心跳。
- 官方数字是速度 2 倍、读缓存 token 2–4 倍；单机本地没有团队分摊这笔账，token 翻倍的代价比在云端更直接。
- 主动模式没有预先写好的规则就放开，等于让 agent 自己发明需求；原型里明确要求规则先立、且默认 observe 只记录不动手。

## 读代码入口

- docs/007-architecture.md：五层拆分与 router/worker 边界的原始定义，先看它判断要不要拆层。
- src/core/engine.ts：主循环所在，看工具调用是不是启动即返回，全双工到底落在哪一行。
- src/app/outbox.ts：异步结果作为新消息回投的出站落点，watchdog 的介入最可能挂在这条链上。
- src/executor/：执行环境抽象与本地 daemon 的接口边界，BYOM 的成本全在这里。
- src/sources/：事件来源与两级过滤的 fast path（来源/白名单）在入口处怎么切。
