## 怎么导入

### 应用内

1. 打开「史料」页。
2. 点右上「导入全文」。
3. 填书名/作者/朝代，选择一个或多个 `txt` / `md` / `html` 文件。
4. 点「导入并切分」。应用会去掉 HTML 标签，按句号/分号/换行切 passage，并写入 `sources` / `source_passages`。

### 命令行（开发用）

```text
node tools/import-local-corpus.mjs <目录> <书名> [作者] [朝代]
```

脚本会递归读取目录下的 html/txt/md，按文件名排序，逐个调用 `production_local_corpus_import`。应用需要带 CDP 9222 运行。

## 检索与回填

- 补原文时，如果候选没有 URL，或 URL 是目录页，先查本地 passage；本地没有命中才走联网检索。
- 本地检索用 4 字重叠评分，完全包含原句时加 1000 分；最多取 3 段。
- `normalized_text` 用 OpenCC `TSCharacters.txt`（Apache-2.0）把繁体归一成简体；`original_text` 保留原字。这样简体笔记能搜到繁体原文，卡片仍显示原字。
- 命中后仍要过逐字校验：模型只能从 passage 里挑连续原文，不能自己写。成功写回 `source_id` / `passage_id` / `provider = local-corpus`，卡片显示「本地库」。

## 简体显示

三本底本是繁体 EPUB。阅读器、书名/作者、出处卡片和史料库原文在视图层统一转简体（OpenCC `TSCharacters`，4,152 字映射）；`original_text` 仍保存繁体原字，搜索和逐字校验不变。

这是显示层的繁→简，不换底本，也不是学术校勘；异体字/避讳字仍可能保持原形。

## 阅读全文

本地书进入详情页后是连续正文阅读器，不是逐句卡片列表：

- 每页 **200 个分句**，服务端按句末标点重新组合成 13–14 个自然段；
- 17px 衬线、2em 首行缩进、760px 阅读宽度；
- 显示 `1–200 / 258,436 段`、页码和跳页；
- 搜索框走 FTS5 `trigram` 索引（不是 `LIKE` 扫描），20 个查询 p50 288ms / p95 297ms / max 304ms；
- 命中后跳到对应页并滚到高亮；
- 「卷/篇」下拉按 EPUB 文件标题列出 504 个卷篇，可按卷跳页；
- 「复制本页」复制当前正文。

实测《资治通鉴》：

- 首屏 200 段 / 约 4,000 字 / 13–14 段
- 搜索「泗水冰合」：第 576 页，1 处命中，高亮在视口内（滚动 700px）
- 20 查询 p95 297ms；阅读请求 283ms；目录接口 62ms
- DB 324,308,992 B（FTS 索引约占 +150MB）

已知问题：分句重组不是原书自然段；卷/篇来自 EPUB 文件标题，不是校勘目录；正文含 EPUB 的编者注/脚注数字，未清洗；全量二十四史前需要压索引体积和导入耗时。

## 已知限制

- 只导入了三本，不是二十四史全量。
- 检索是 4 字重叠 + 扫描 `LIKE`，不是 FTS/向量检索；大库再扩时需要建索引。
- 繁简归一能覆盖常见字，但异体字/避讳字仍可能漏；漏了会回退联网。
- 导入是按文件顺序拼接，没有保留原书的卷/篇结构；`chapter` 目前统一写「全卷」。
- 安装包不包含语料，换机器需要重新导入。
- 本地原文保留繁体，和正文简体不一致时会在出处卡片里表现为差异；这是有意保留原字。
