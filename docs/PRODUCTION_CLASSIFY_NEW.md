# 生成内容的归类与新标记

> 目标：制作台生成笔记后，让用户选择「自动归类」或「指定位置」；没看过的生成内容在侧栏有清晰但不吵的「新」标记，帮助快速定位。

---

## 1. 调研结论（2026）

### 1.1 「新 / 未读」标记

| 产品 / 模式 | 做法 | 可借鉴 / 要避免 |
| --- | --- | --- |
| Google Docs 评论 | 未读评论是**蓝点**，悬停展开成 **New** 文本标签；工具栏用数字角标，计数到 9+ | 文本标签比纯色点更可理解；清除用「上次查看时间」而不是逐条已读 |
| Gmail 2026 iOS 改版 | 未读用**远端蓝点**，正文加粗对比被削弱 | 2026 年评测批评「全都一样」、蓝点离标题太远；**不要把标记放到远离标题的角落** |
| Slack / Linear | 未读用**加粗 + 小圆点/计数**，点开即清 | 计数适合「待办队列」，笔记列表更适合低压力标记 |
| 低压力通知（Dribbble 概念） | 主题色**小圆点**，不用红点和数字，避免制造焦虑 | 笔记不是待办，不该用红色警报 |
| 角标分类（UX Pattern Lab / HCI 指南） | 点=环境提示，数字=行动队列，文本标签=明确状态 | 「新」是内容回忆信号，不是行动队列，优先**文本标签**而不是数字 |
| Notion / Readwise 类 | 侧栏/列表用 **New** 标签或未读计数，打开后消失 | 标签要靠近标题，颜色跟随主题 |

**结论：**
- 用**小号文本标签「新」**，不用红点、不用数字角标。
- 放在**标题同一行的文字区**（不是最右侧的 pin 位置），保证左→右扫描能看见；打开笔记后立即消失。
- 颜色用主题蓝（`--blue-soft` 底 + `--blue` 字），暗色模式复用同一组 token；字号 12px，满足现有可读性下限。
- 另加一个「新 N」筛选入口，点开只看未看的生成内容；没有新内容时不显示。

### 1.2 自动归类

| 来源 | 做法 | 可借鉴 |
| --- | --- | --- |
| 自动整理专利（US20260080248A1） | 模型把内容映射到**已有文件夹**，按置信度分级给建议，移动前可确认 | 只选已有文件夹；低置信度分级处理 |
| Markd「Strict Librarian」 | 只给模型已有文件夹清单，禁止新建；输出 `none` 表示不适配；JSON 校验 + 文件夹白名单 + 重试 | **封闭清单 + 白名单校验**，不合法就跳过 |
| Reso「没有未分类」 | 不给「未分类」兜底，低置信度也标记后归位；用户手动移动过的永不被机器覆盖 | 人工移动优先；归类结果要可见 |
| Topic Matching | 输出主/次领域 + 置信度；置信度差距 <10% 或内容太短时拒绝猜测 | 不确定时宁可回退，不要硬分 |
| Fabric.so 评测 | 「把东西分错还非常自信」是自动归类的核心风险 | 低置信度回退 + 记录理由 + 可回退 |

**结论：**
- 自动归类**只能从当前笔记库已有文件夹中选择**，不允许新建文件夹。
- 模型输出 JSON：`{"folder":"...","confidence":"high|medium|low","reason":"..."}`；`high/medium` 且文件夹在白名单里才采用，否则回退到 **`待整理`**。
- 每次自动归类都把「选了什么、为什么」写进任务日志；不静默改用户已经手动移动过的笔记（归类只发生在生成入库时）。
- 模型调用失败、未配置 AI、文件夹列表为空，都回退 `待整理`，不阻塞制作。

## 2. 交互设计

### 2.1 制作向导（第 3 步「选项」）

新增「入库位置」：

```
入库位置
( ) 自动归类   模型从已有文件夹里选；没把握时放回「待整理」
(•) 指定位置   [ 待整理 ▾ ]
```

- 默认「指定位置 / 待整理」，与用户当前把自动产物放待整理的习惯一致。
- 「指定位置」下拉列出笔记库已有文件夹（`listFolders`），默认 `待整理`。
- 第 4 步确认摘要显示：`入库位置：自动归类` 或 `入库位置：待整理`。
- 自动归类的结果不弹窗确认；任务日志里能看到「自动归类：历史（…理由）」。用户不满意可以像普通笔记一样拖动/移动。
- 订阅自动任务（UP 更新）默认仍进 `待整理`；本次不把订阅也改成模型归类，避免每个自动任务都产生额外模型调用。

### 2.2 侧栏「新」标记

- 笔记行：标题后、标注数之前放一个 **`新`** 胶囊：
  - 12px 字号、16px 高、4px 圆角、`--blue-soft` 底、`--blue` 字；
  - 暗色模式同一 token；不红、不闪、不加动画；
  - `aria-label="尚未查看"`，文本本身可读，不依赖颜色。
- 打开笔记即清除：点击行进入笔记页时本地立即移除标记，同时写回后端；从图谱/深链进入也通过路由 activeId 清除。
- 侧栏筛选：搜索框下方出现「新 N」小按钮（N>0 时）；点击只看新笔记，再点恢复目录树。为空时显示「没有未看的笔记」。
- 已读状态跨设备同步：`note_new` 进入同步表；一台设备看过，另一台也清除。旧笔记不会突然全部变成「新」，只有功能上线后新生成并入库的笔记才会写入 `note_new`。

## 3. 数据与接口

### 3.1 制作选项

`JobOptions` 新增：

```rust
pub destination: String, // "" 旧行为；"auto" 自动归类；"folder" 指定位置
pub folder: String,      // 指定位置的相对路径，例如 "待整理"
```

兼容：旧任务没有这两个字段，`serde(default)` 得到空值，走原来的「手动→ScribeFlow / 自动→待整理」。

### 3.2 自动归类

`src-tauri/src/production/classify.rs`：

- 候选文件夹 = `vault::walk_folders(root)`，排除 `ScribeFlow`、`.trash`、`.yebian` 等内部目录；候选为空或没有 AI 配置时不调用模型。
- 提示词只给候选文件夹 + 标题 + 正文前 2000 字；要求只输出 JSON。
- 校验：
  - 从返回内容里提取 JSON（允许代码围栏）；
  - `folder` 去除首尾 `/`，必须与候选（或 `待整理`）精确匹配（大小写不敏感）；
  - `confidence` 必须是 high/medium；low/缺失/非法 JSON/文件夹不在白名单 → `待整理`。
- 返回 `{folder, confidence, reason, prompt_tokens, completion_tokens}`；token 计入任务用量和成本。
- 日志：`自动归类：<folder>（<reason>）`；回退时记录原因。

### 3.3 入库

`publish` 接收解析后的 `folder`：
- 自动归类 → 模型选中的文件夹；
- 指定位置 → 用户选择的文件夹；
- 旧任务 → `auto` 任务进 `待整理`，手动任务保持空（ScribeFlow/ 根）。

文件夹做路径安全校验（拒绝绝对路径和 `..`），非法回退 `待整理`。

### 3.4 「新」状态

用户库新增本地/同步表：

```sql
CREATE TABLE IF NOT EXISTS note_new (
  note_id TEXT PRIMARY KEY,
  created_at INTEGER NOT NULL
);
```

- 制作入库成功后写入 `note_new(note_id, now)`；重新生成同一篇会刷新 `created_at`，重新变成「新」。
- 笔记列表查询 `EXISTS(SELECT 1 FROM user.note_new WHERE note_id = n.id) AS is_new`。
- `NoteMeta` 增加 `is_new: bool`（camelCase `isNew`）。
- `mark_note_seen(note_id)` 删除该行；打开笔记时调用。
- `note_new` 加入同步表（pk `note_id`），已读/未读跨设备一致；删除会作为墓碑同步。
- 旧笔记没有 `note_new` 行，不会显示「新」。

## 4. 验收

- 单元：归类 JSON 解析（合法/代码围栏/非法文件夹/低置信度/空候选）；文件夹安全校验；`note_new` 与 `list_notes` 的 `is_new`。
- 制作链路：用 mock AI 跑一次「指定位置 / 待整理」和一次「自动归类」，确认最终路径和日志；自动归类失败时回退 `待整理`。
- 列表：生成一篇新笔记 → 侧栏出现「新」；打开后消失；「新 N」筛选可用；重启后状态保持；同步到第二台设备仍显示「新」，在一台看过另一台清除。
- 视觉：截图检查 1440/1040、明/暗，文字不溢出、标记不压标题、暗色对比度达标。
- 构建：`cargo test --lib`、`npm run build`。

---

## 5. 诚实清单

- 自动归类会产生一次额外模型调用（输入是候选文件夹 + 标题 + 正文前 2000 字），有 token 成本和几百毫秒到几秒延迟；失败/低置信度回退 `待整理`。
- 归类只发生在生成入库时；用户之后手动移动过的笔记不会被机器再改。
- 模型可能选错文件夹；本次不做「置信度 UI/一键撤销归类」，结果会写日志，用户可手动移动。
- 「新」只覆盖功能上线后生成并写入 `note_new` 的笔记；旧笔记不追溯标记。
- 已读状态同步依赖 `note_new` 表；如果同步关闭，两台设备的「新」状态各自独立。
- 订阅自动任务本次仍固定 `待整理`，没有在订阅表单里加「自动归类」开关。
- 侧栏「新 N」筛选是平面列表，不保留目录层级；新笔记少时够用，量很大时再考虑分组。
- 自动归类的候选文件夹来自当前 vault 的物理目录；刚建但还没被扫描到的文件夹可能不在候选里。
